# BBVoxi 1.4.0 · 全量审查与修复报告

> 对应发布版本：[1.4.0](./RELEASE_v1.4.0.md) ｜ 审查日期：2026-10-07 ｜ 上一份报告：[全量审查与修复报告-v1.3.1.md](./全量审查与修复报告-v1.3.1.md)

本报告记录 **1.4.0** 这一轮"全仓库代码审查与清理"的完整过程：审查方法、逐项清单、
验证方式，以及**故意不修 / 有意保留**的事项及原因。

本轮与前几轮不同：**不改功能行为**，只做"规范轴 + 死代码轴"双轴清理——
把 `cargo clippy` 的历史告警清到零、删掉已断头路的死代码与死字段、清掉无用目录与历史临时产物，
并逐个核实在用依赖与 windows feature，确认**无死依赖**。

## 1. 审查范围与方法

| 项 | 内容 |
|---|---|
| 范围 | **全部模块**（15 个 `src/*.rs`），不是只审差异 |
| 方法 | 按 `TRAE-code-review` 技能流程：定范围 → 取证 → 推断意图 → 扫描问题 → **交叉验证** → 输出 → 修复 → 验收 |
| 双轴 | ①**规范轴**：`cargo clippy --all-targets` 的全部告警；②**死代码轴**：只被废弃脚本/测试读取的代码、无用字段、无用文件、无用依赖 |
| 判定基线 | 仓库自身约定（各模块"为什么"注释 + 前几轮报告的取舍原则）+ Fowler 坏味道基线（判断题，仓库约定可覆盖） |
| 结论 | 规范轴 **15 条告警全部清零**；死代码轴清理 **1 处测试 + 5 个死字段 + 3 个无用目录 + 10 个历史临时产物**；依赖与 feature 核实**全部在用** |

**验证基线（改动前后对照）**

| 项 | 改动前 | 改动后 |
|---|---|---|
| `cargo test --bin bbvoxi` | 190 passed / 0 failed / 4 ignored | **197 passed / 0 failed / 4 ignored** |
| `cargo clippy --bin bbvoxi --all-targets` | 15 条历史告警 | **0 条** |
| `cargo build --release` | ✅ | ✅（8,394,752 字节） |

> 注：测试条数从 190 涨到 197 是**新增功能**带来的（页签布局回归、主题、个人词典、识别语言），
> 不是本轮清理新增；本轮清理反而**删掉**了 1 条测试（见 §3.1）。

全部为"写法不规范 / 可简化 / 与新版 lint 约定不符"，**不改变任何运行行为**：

| 4 | `Copy` 类型的方法不该用 `&self`（多余借用） | [hotkey.rs](file:///d:/AI/Github/BBVoxi/BBVoxi/src/hotkey.rs#L74) | `to_config(&self)` → `to_config(self)` |
| 5 | `.then(\|\| x)` 应写 `.then_some(x)`（更直接、不做多余闭包） | [typer.rs](file:///d:/AI/Github/BBVoxi/BBVoxi/src/typer.rs#L75)、[session.rs](file:///d:/AI/Github/BBVoxi/BBVoxi/src/session.rs#L788)、hotkey.rs 测试 | 全部改 `.then_some(...)` |

## 3. 死代码轴：删掉"没人用"的代码

### 3.1 死代码：布局 JSON 导出测试（1 条）

- **是什么**：`dump_layout_for_review` 测试——把界面布局量到的矩形写成 JSON 文件。
- **为什么是死代码**：它的**唯一消费者**是前几轮做界面改版时用过的一个临时验收脚本；
  改版完成后脚本已被删除（见 §4），这条测试就成了**断头路**：跑它只会在仓库里生成一个没人读的 JSON 文件。
- **修法**：连同它带来的**死字段**一起删除。
- **位置**：`src/ui.rs` 测试模块。

### 3.2 死字段：只被上面那条测试读取（5 个）

删掉 `dump_layout_for_review` 后，`cargo clippy` 立刻暴露出这些字段"除了那条测试没人读"：

| 字段 | 位置 | 说明 |
|---|---|---|
| `Text.color` | ui.rs | 只在导出 JSON 时用 |
| `RectI.x` | ui.rs | 只在导出 JSON 时用 |
| `RectI.stroke` | ui.rs | 只在导出 JSON 时用 |
| `RectI.sw` | ui.rs | 只在导出 JSON 时用 |
| `RectI.cr` | ui.rs | 只在导出 JSON 时用 |

**验证**：删掉后 clippy 不再报"字段从未被读取"，且**真实的布局回归测试全部保留**
（`content_is_compact` / `no_text_overflows_the_window` 等仍常驻，见 [RELEASE_v1.4.0.md](./RELEASE_v1.4.0.md) 第 7 节）。

### 3.3 无用的环境依赖与文件核实

- **无死依赖**：逐个核实 **23 个 Cargo 依赖**、**10 个 windows feature**、所有 `pub const` 公开常量，
  **全部在用**（含腾讯签名专用的 `base64` / `hmac` / `sha1` / `percent-encoding`——它们不直观但确被签名函数调用）。
- **删除的目录（3 个，工具残留）**：`untitled-project/`、`.commandcode/`、`.workbuddy/`
  ——都是本机开发工具留下的残留目录，与软件功能无关，且未入库。
- **删除的文件（10 个，`docs/` 下历史 UI 验收临时产物）**：
  `_ui_after_900.png`、`_ui_compare_real.png`、`_ui_compare.png`、`_compare.py`、
  `_ui_new_full.png`、`_layout_new.json`、`_ui_now_full.png`、`_ui_now.png`、
  `_draw_layout.py`、`_layout_now.json`——都是前几轮界面改版时的**一次性验收中间产物**，
  已无对应脚本读取（与 §3.1 是同一批断头路）。
- **顺带修掉指向已删图片的死链接**：README 与 [版本历史.md](./版本历史.md) §5 曾指向已删除的
  `docs/_ui_compare_real.png`，已改为不再引用。

## 4. 重复设计核查与"有意保留"

审查中确实发现了**疑似重复**的设计，但逐条核实后判定为**应保留**，理由如下：

| 疑似问题（Fowler 坏味道） | 位置 | 判定 | 理由 |
|---|---|---|---|
| `Backend` 枚举上 5 个**各自 match 三家**的方法（看起来像 Repeated Switches） | asr/mod.rs | **保留** | 三家协议**解析签名互不相同**（千问/豆包/腾讯的事件结构、结束条件、错误码都不同），抽成统一 trait 只会**多一层间接**、把各家的差异藏进分支，违背仓库"简单能用"原则 |
| 三家 `asr/*.rs` 各自实现连接与解析 | asr/qwen.rs、doubao.rs、tencent.rs | **保留** | 同上：三家 WebSocket 握手、鉴权头、帧格式完全不同，强行合并会造成"一处改三家都怕"的脆弱耦合 |

> 结论：**本轮不引入任何新抽象**。仓库约定高于 Fowler 基线——坏味道是"判断题"，
> 当抽象只会增加间接层、不减少真实重复时，保持现状才是对的。

## 7. 刻意不做 / 保留项（如实说明）

- **不做无意义抽象**：见 §4，`Backend` 与三家解析保持各自实现。
- **不动 `cargo fmt` 的历史漂移**：`cargo fmt --check` 仍有历史格式差异，
  这是仓库与新版 rustfmt 的**已知漂移**（见 [版本历史.md](./版本历史.md) §4），
  发布会重排大量无关代码，收益为零、风险不为零，**本轮同样不动**。
- **不改任何默认值与配置格式**：本轮是清理，配置版本号（3）与字段定义**原样不变**。
