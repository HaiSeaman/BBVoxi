# BBVoxi 版本历史

本目录用于维护 **BBVoxi 各版本的发布说明**。
每发布一个新版本（包括修复版、功能版、首发版），都应：

1. 新建 `docs/RELEASE_<版本号>.md`（例如 `docs/RELEASE_v1.0.0.md`）
2. 在本文档 §2「版本索引」新增一行
3. 在 `Cargo.toml` 同步版本号
4. 重新构建发布包并记录 SHA-256 到该版本的发布说明
5. 在 `README.md` 的"最新版本"行更新

> 命名约定：`RELEASE_v<SemVer>.md`，正文用中文。SemVer 形如 `1.0.0` / `1.1.2` / `2.0.0-beta.1`。

---

## 1. 版本号规则

按 [Semantic Versioning 2.0.0](https://semver.org/lang/zh-CN/)：

| 段 | 何时递增 | 例如 |
|---|---|---|
| **Major** | 破坏性变更（如弃用 ASR 厂商、改协议、改注入实现） | `0.x → 1.0` |
| **Minor** | 新增向后兼容功能（新增 ASR 厂商、新设置项、新 UI） | `1.0 → 1.1` |
| **Patch** | 向后兼容的修复（bugfix、依赖升级、文档修正） | `1.1.0 → 1.1.1` |

预发布标签：`1.2.0-rc.1`、`2.0.0-beta.3` 等。

## 3. 写作模板（每次发布前复制）

新建 `docs/RELEASE_v<版本号>.md`，按以下章节组织（详见 1.0.0 实例）：

1. **包信息**（文件名、大小、SHA-256、构建时间、PE 资源校验）
2. **一句话定位**（不超过 50 字）
3. **系统要求**
4. **安装与首次运行**
5. **支持的 ASR 服务商**（如本版本有变化）
6. **完整功能清单**（按"新增 / 改进 / 修复"分区）
7. **技术亮点**（架构图、关键算法、踩坑与经验）
8. **模块清单**（如本版本有新增/删除模块）
9. **路径与产物**
10. **测试矩阵**
11. **已知问题与限制**
12. **升级指南**（从上一版本升级）
13. **安全与隐私声明**（如本版本有变化）
14. **反馈渠道**
15. **版权与许可**
16. **附：本版本发布检查表（已勾）**

## 4. 发布流程（手动 GitHub）

> 本项目不接入 CI/CD，由维护者手动发布。每发一版建议都把整个流程过一遍，确保可追溯。

1. **版本号三处同步**
   - `Cargo.toml` 的 `[package].version`
   - 标题：本文档 §2 索引行
   - 顶层 `README.md` 顶部"最新版本"行
2. **构建**
   ```bash
   cargo fmt --check
   cargo test                                # 必须 0 失败
   cargo build --release
   mkdir -p dist
   cp target/release/bbvoxi.exe dist/BBVoxi-<版本号>.exe
   ```
   > **关于 `cargo fmt --check`**：仓库里若干历史文件与**较新版本的 rustfmt** 存在格式差异（例如调用参数超过
   > `fn_call_width` 启发式阈值时的换行方式），因此这条检查在本地可能**报错但不是代码问题**。
   > 想彻底统一，执行一次 `cargo fmt` 并单独提交即可（纯格式变更）。发布不依赖它。
3. **校验产物**
   ```powershell
   Get-FileHash dist\BBVoxi-<版本号>.exe -Algorithm SHA256
   ```
   与新版 `RELEASE_v<版本号>.md` 中填入的值一致。
4. **Git 提交**
   ```bash
   git add .
   git commit -m "release: v<版本号> — <一句话主题>"
   git tag v<版本号>
   git push --follow-tags
   ```
5. **GitHub 发版**
   - 进入仓库 → **Releases** → **Draft a new release**
   - Choose tag：`v<版本号>`
   - Release title：`BBVoxi <版本号> — <一句话主题>`
   - 粘贴 `docs/RELEASE_v<版本号>.md` §1（包信息）作为正文开头，正文末尾附一段一句话总结
   - 上传 `dist/BBVoxi-<版本号>.exe` 作为二进制资产
   - **Publish release**

## 5. 历史里程碑（叙述）

### 1.2（2026-09-18）— 全量审查与健壮性修复
起因：上一轮修「实时输入把字/退格打到别的程序里」时改到一半中断，本轮把 14 个模块重新逐行过了一遍。
共修 6 项：①「测试识别」此前会把结果打进设置窗背后的程序（违反 README 的明文承诺，从 1.0 起就存在）；
② 收尾阶段不重查前台窗口 —— 上一版只补了实时阶段，**松手后等最终结果期间切窗口仍会打错地方**；
改法不是再补一次调用，而是把窗口校验做成 `sync/finish` 的**必填参数**，让"忘记校验"编译不过；
③ 腾讯/豆包把「结束标记」与「最后一句文本」放在同一个包里，解析先判 `slice_type` 导致 `done` 永不置位、
松手后白等 8 秒超时（顺带发现豆包也有同样问题）；④ 低于 16kHz 的麦克风（蓝牙耳机免提模式常见 8kHz）
不会被升采样，音频被慢放一倍送出、识别基本乱码；⑤ 切窗口后两种设置行为不一致（开着实时输入=一字不打，
关着=整段打进新窗口），统一为"一律放弃输入"；⑥ 若干小毛病与文档漂移。
单元测试 56 → 82 条，另做了变异检查（把 7 处修复逐个改坏，8 条测试对应失败）证明测试有效。
详见 [RELEASE_v1.2.md](./RELEASE_v1.2.md) 与 [全量审查与修复报告-v1.2.md](./全量审查与修复报告-v1.2.md)。

### 1.1（2026-09-11）— 代码质量加固 + 设置界面改版
修复一批真实缺陷：裸按键 keyup 被吞导致"按键卡住"、识别开关（自动标点/口语顺滑）对部分服务商是摆设、
托盘菜单退出后图标残留、日志时间戳不可读、会话线程启动失败静默。新增：**双击 BBVoxi.exe 唤醒后台实例并弹出设置窗**。
设置界面重新排版（服务商分段选择器、密钥就地显示、通用卡片、状态行拆分、识别选项禁用注明等）。
单元测试 52 → 56。详见 [RELEASE_v1.1.md](./RELEASE_v1.1.md)。

### 1.0.0（2026-09-10）— 首发
从 `0.x` 内部快照演进到正式版，补齐 README / `.gitignore` / 图标资源 / 文档。详见 [RELEASE_v1.0.0.md](./RELEASE_v1.0.0.md)。
