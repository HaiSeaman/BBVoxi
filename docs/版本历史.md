# BBVoxi 版本历史

本目录用于维护 **BBVoxi 各版本的发布说明**。
每发布一个新版本（包括修复版、功能版、首发版），都应：

1. 新建 `docs/RELEASE_<版本号>.md`（例如 `docs/RELEASE_v1.0.0.md`）
2. 在本文档 §2「版本索引」新增一行
3. 在 `Cargo.toml` 同步版本号
4. 重新构建发布包并记录 SHA-256 到该版本的发布说明
5. 在 `README.md` 的"最新版本"行更新

> 命名约定：`RELEASE_v<SemVer>.md`，正文用中文。SemVer 形如 `1.0.0` / `1.1.2` / `2.0.0-beta.1`。

---

## 1. 版本号规则

按 [Semantic Versioning 2.0.0](https://semver.org/lang/zh-CN/)：

| 段 | 何时递增 | 例如 |
|---|---|---|
| **Major** | 破坏性变更（如弃用 ASR 厂商、改协议、改注入实现） | `0.x → 1.0` |
| **Minor** | 新增向后兼容功能（新增 ASR 厂商、新设置项、新 UI） | `1.0 → 1.1` |
| **Patch** | 向后兼容的修复（bugfix、依赖升级、文档修正） | `1.1.0 → 1.1.1` |

预发布标签：`1.2.0-rc.1`、`2.0.0-beta.3` 等。

## 3. 写作模板（每次发布前复制）

新建 `docs/RELEASE_v<版本号>.md`，按以下章节组织（详见 1.0.0 实例）：

1. **包信息**（文件名、大小、SHA-256、构建时间、PE 资源校验）
2. **一句话定位**（不超过 50 字）
3. **系统要求**
4. **安装与首次运行**
5. **支持的 ASR 服务商**（如本版本有变化）
6. **完整功能清单**（按"新增 / 改进 / 修复"分区）
7. **技术亮点**（架构图、关键算法、踩坑与经验）
8. **模块清单**（如本版本有新增/删除模块）
9. **路径与产物**
10. **测试矩阵**
11. **已知问题与限制**
12. **升级指南**（从上一版本升级）
13. **安全与隐私声明**（如本版本有变化）
14. **反馈渠道**
15. **版权与许可**
16. **附：本版本发布检查表（已勾）**

## 4. 发布流程（手动 GitHub）

> 本项目不接入 CI/CD，由维护者手动发布。每发一版建议都把整个流程过一遍，确保可追溯。

1. **版本号三处同步**
   - `Cargo.toml` 的 `[package].version`
   - 标题：本文档 §2 索引行
   - 顶层 `README.md` 顶部"最新版本"行
2. **构建**
   ```bash
   cargo fmt --check
   cargo test                                # 必须 0 失败
   cargo build --release
   mkdir -p dist
   cp target/release/bbvoxi.exe dist/BBVoxi-<版本号>.exe
   ```
   > **关于 `cargo fmt --check`**：仓库里若干历史文件与**较新版本的 rustfmt** 存在格式差异（例如调用参数超过
   > `fn_call_width` 启发式阈值时的换行方式），因此这条检查在本地可能**报错但不是代码问题**。
   > 想彻底统一，执行一次 `cargo fmt` 并单独提交即可（纯格式变更）。发布不依赖它。
3. **校验产物**
   ```powershell
   Get-FileHash dist\BBVoxi-<版本号>.exe -Algorithm SHA256
   ```
   与新版 `RELEASE_v<版本号>.md` 中填入的值一致。
4. **Git 提交**
   ```bash
   git add .
   git commit -m "release: v<版本号> — <一句话主题>"
   git tag v<版本号>
   git push --follow-tags
   ```
5. **GitHub 发版**
   - 进入仓库 → **Releases** → **Draft a new release**
   - Choose tag：`v<版本号>`
   - Release title：`BBVoxi <版本号> — <一句话主题>`
   - 粘贴 `docs/RELEASE_v<版本号>.md` §1（包信息）作为正文开头，正文末尾附一段一句话总结
   - 上传 `dist/BBVoxi-<版本号>.exe` 作为二进制资产
   - **Publish release**

## 5. 历史里程碑（叙述）

### 1.4.0（2026-10-07）— 设置界面页签化 + 千问 3.1 + 个人词典与识别语言 + 全仓库清理

本版是一次"**功能补齐 + 界面重做 + 代码体检**"的合并版本，分三块。

**一、设置界面页签化（1.4.0 起）**：把旧版"单张长卡片 + 说明全塞悬停气泡"改成**顶部三页签**——
「语音服务」（服务商 / 凭据 / 个人词典）、「识别选项」（全部识别开关 + 识别语言）、「通用」（快捷键 / 开机自启 / 主题）。
每行是"标题 + 一句说明 + 右侧控件"的紧凑行卡，说明文字直接写在行里（不用再悬停）；窗口加宽到 580（最小 520）。
新增**三种主题**（跟随系统 / 浅色 / 深色），点一下**立即生效并落盘**——落盘写的是"上一次保存的配置 + 新主题"，
**不是**编辑中的整份配置（否则主人填了一半还没保存的 API Key 会被顺手带进文件）。
底部「最近识别」反馈条继续钉在窗口底，任何页签都看得见。无窗口布局探针把这套改版纳入常驻回归：
`content_is_compact`（每页一屏放得下、卡片恰好 1 张）、`no_text_overflows_the_window` 等。

**二、千问升级 3.1 + 个人词典 + 识别语言**：

- **千问 3.1**：默认模型 `qwen-audio-3.0-asr-flash-streaming` → `qwen-audio-3.1-asr-flash-streaming`，
  老配置**自动迁移**（精确匹配旧默认值才升，主人自己填过的模型名原样保留，与快捷键迁移同套路；配置版本 2 → 3）；
  同时补上近场 `vad_model = near_meeting_16k`（官方默认是远场会议）、显式打开 `intermediate_result_enabled`（官方默认关）。
  顺带修掉一个潜伏缺陷：**「口语顺滑」开关对千问一直是摆设**——`disfluency_removal_enabled` 从未传过，界面也写着"暂不支持"，现在真正接通。
- **个人词典（热词）**：设置窗填一行一个词（人名、品牌、术语）。千问走**双通道**（`vocabulary` 即时热词 + `input.context` 上下文增强），
  豆包走 `request.context`（官方格式是**序列化后的 JSON 字符串** `{"hotwords":[{"word":"…"}]}`，不是嵌套对象）；
  腾讯的热词要在控制台预建词表拿 ID，本程序未接，界面如实注明"此处不生效"。
- **识别语言**：十选一（自动 / 中文 / 英语 / 粤语 / 日语 / 韩语 / 法语 / 德语 / 俄语 / 西班牙语）。
  豆包适配官方 `language` 参数（BCP-47），但该参数**只在整句端点上生效**，所以选语言会**自动切 `bigmodel_nostream` + `StreamMode=1`**；
  腾讯按语言映射引擎（`16k_zh` / `16k_yue` / `16k_en` / `16k_ja` / `16k_ko`），法德俄西没有实时引擎会**明确报错**而不是拿中文引擎瞎认；
  千问模型自身多语种自动检测，无需参数。老配置无这两个字段时靠 `serde(default)` 落回默认（空词表 / 自动），**行为与升级前完全一致**。

**三、全仓库代码审查与清理**：`cargo clippy` 的 15 个告警全部清零（错误码数字分组歧义、手写 `Default`、
`Copy` 类型用 `&self`、多余 `return`、`.then(||)` 应为 `.then_some`、文档列表续行缩进、`static` 定义位置、
`Default::default()` 后再赋值字段等）；删掉一处**死代码**（布局 JSON 导出测试——它的唯一消费者是已废弃的验收脚本，
断头路）与其带出的**死字段**（`Text.color`、`RectI.x/stroke/sw/cr`）；清掉**无用文件**
（`untitled-project/`、`.commandcode/`、`.workbuddy/` 三个工具残留目录 + `docs/` 下 10 个历史 UI 验收临时产物）。
逐一核实后确认：**23 个 Cargo 依赖、10 个 windows feature、所有公开常量全部在用**（含腾讯签名专用的 base64/hmac/sha1/percent-encoding），无死依赖。
审查中**有意保留**了 `Backend` 枚举那 5 个各自 match 三家的方法——三家解析签名互不相同，抽 trait 只会加一层间接，违背"简单能用"原则。

**过程**：单元测试 190 → **197 条全绿**，clippy 零告警。产物自检：exe 内含界面版本串 `v1.4.0`、
不含旧串 `v1.3.3`、且含千问 3.1 模型串。详见 [RELEASE_v1.4.0.md](./RELEASE_v1.4.0.md) 与 [全量审查与修复报告-v1.4.md](./全量审查与修复报告-v1.4.md)。

### 1.3.3（2026-09-30）— 界面重排（方案 C）+ 7 条"丢字 / 重复打字 / 静默失败"硬伤修复

起因：主人要一份界面与代码的全面体检。先出了一份**只诊断、不改代码**的报告
（[UI界面审查与重构建议报告](./UI界面审查与重构建议报告.md)）：它用 egui 的**真实布局代码导出绘制指令**
量出"内容总高 1274px、768 高的笔记本上「最近识别」在 599px 处根本看不见、5 张卡里 30% 的高度是说明小字"，
并按 WCAG 公式实测出浅色主题 10 处对比度不达标（成功绿 3.37、胶囊上的字 2.88）。主人拍板：按"方案 C"重排界面，
并修两批共 7 条硬伤。

**界面（方案 C）**：5 张卡合并成 2 张（品牌栏＋「最近识别」＋一张设置卡），结果卡提到品牌栏正下方；
说明小字全部收进悬停气泡（`i` 图标）——一句话没删，页面却干净了；品牌栏压到 42px；
底部按钮 140/104/96 → 130/104/92；卡片加柔和投影、切换加 0.12 秒过渡、滚动条平时隐藏。
**内容总高 1274 → 692px，「最近识别」599px → 98px，900 高的屏幕一屏看全。**
配套修复：浅色主题的成功/警告/危险色加深到 6.2:1 以上（原 3.37/3.38）、状态胶囊上的小字 2.88 → 5.0+、
被禁用的说明文字从"等于隐形"（1.99）提到 5.5:1；状态消息 10 秒后自动退场（原来一条「已保存」会永远挂着）；
点 ✕ 关窗时若有未保存改动会先问一句（保存并关闭 / 不保存 / 取消）；字号收敛到 4 档语义名；
把"只比红通道差值"的**假对比度单测**换成真 WCAG 公式——它一次抓出 10 处不达标。

**功能硬伤（两批共 7 条）**：

1. **中途失败不再丢字**：麦克风异常 / 推流失败 / 推流超时以前直接 `return`，跳过了"给服务端发结束指令、
   松手后等最终结果、正常关闭"三件事——服务端其实已经把这句话定稿了却没人去取，「最近识别」停在上一次。
   现在失败与正常路径**共用同一套收尾**（发结束帧 → 等最终结果 → 关连接），结果照样交付
   （能打字就打字、否则进剪贴板），并如实报出失败原因。
2. **会话线程起不来界面看得见**（以前只写日志：按快捷键毫无反应，而托盘与设置窗一切正常）。
3. **生僻字 / emoji 的退格数按 UTF-16 编码单元算**（按"字符"算会少退一位，在目标程序里留下半个代理对的乱码）。
4. **注入部分失败不再整段重粘**：跨批次被拒时以前会丢掉"已经打进去多少"的记账，于是把整段再粘一遍
   —— 目标程序里出现两份同样的字。现在只补没进去的尾巴。
5. **陈旧错误码不再误判**：`SendInput` 前先清错误码，只在"一个事件都没进去"时才读它
   （否则几百毫秒前留下的"拒绝访问(5)"会把部分成功误判成被 UIPI 拦下，白跳过粘贴兜底）。
6. **注入搬出钩子回调**：回调里直接 `SendInput`，一旦被卡过系统 300ms 的超时，Windows 会**静默摘钩**
   （快捷键全废、Win 键乱弹、日志无痕）。现在回调只把任务丢进通道，注入由专用线程做。
7. **钩子装不上要报出来**（以前只写日志，程序"一切正常"，实际一个键都没接管）。

**过程**：每条修复先写会失败的测试，其中 4 条回归做了**变异验证**（把旧 bug 人为放回去，确认测试真的变红）；
界面改动靠"无窗口布局探针"（跑真实 egui 布局、导出绘制指令再量）验收（当时导出的前后对比图已在 1.4.0 清理时移除）。
终审派了独立子代理通读全部改动，之后又按两轴（规范 / 规格）做了一轮审查：规范轴无硬违规，
规格轴 8 处出入，能改的都改了（含把"正常收尾"与"失败收尾"的重复实现抽成一份共用逻辑、清掉字号残留）。
单元测试 156 → 190 条全绿，`cargo clippy` 零新增告警。
详见 [RELEASE_v1.3.3.md](./RELEASE_v1.3.3.md)。

### 1.3.2（2026-09-25）— 三个"看起来在工作、其实没工作"的坑 + 全量审查加固

起因：主人连续报了三个现象 —— ① 按住 `Ctrl+Win` 说话时会"突然断开"，紧接着像只按着 `Win` 那样
弹出开始界面；② "已复制到剪贴板、按 Ctrl+V 粘贴"这个提示会**弹出软件窗口**；③ 勾了「输入被拒时用
剪贴板粘贴兜底」，可语音输入没进光标/输入框时，剪贴板里**也找不到**那段字。

**① 的根因（顺序问题）**：钩子旧规则是"凑齐组合的那一次按下才吞"。**先按 `Win`、后按 `Ctrl`** 时，
`Win` 的按下在组合未凑齐时被放行给了系统外壳，外壳于是记住了"Win 按下过"；松手时 `held_vk` 记的是
`Ctrl`，`Win` 的 keyup 没被吞 → 外壳看到一次**完整、独立**的 Win 按键 → 必弹开始菜单抢焦点。
日志里 73 次录音 / 73 次松开成对，会话从未自己中断，排除了网络与麦克风侧。
先用 5 个注入探针在真机上把 Windows 的行为测清楚（孤立 Win 松开不弹菜单、完整 Win 按下+松开会弹、
"吞掉泄漏的松开"会让系统此后每敲一个字母都触发 Win+X、"在钩子回调里补发"来不及），确定只剩一条路：
**Win 的按下全程由本程序接管，再按真实意图补发**（组合凑齐→收编、只按 Win→补一整套按下+松开、
`Win+X`→一次 `SendInput` 提交 `[Win↓, X↓]`）。顺序无关，两种按法都不再泄漏。

**② 的根因**：会话线程有一条"请求显示设置窗"的通道，主人切走窗口、结果改走剪贴板时就把窗口顶到
最前面。整条通道删除，提示改走托盘悬浮文字 + 窗口内那行字 + 日志（不打扰、但找得到）。

**③ 的根因（两层）**：一是那个开关的触发条件（`SendInput` 报错/部分提交）**检测不到真正的失败** ——
`SendInput` 只报告"事件已入队"，目标程序收下再丢掉我们完全看不见（实测 Chrome 这类目标连插入符都
不给），所以它从上线至今一次都没触发过；二是兜底粘贴"先存后还"，写完 300ms 被还原，把我们自己写
进去的字又擦掉了。改法：**识别结果默认留一份到剪贴板**（老配置自动迁移，配置 schema 1 → 2）、
去掉自动还原、写完回读核对并把"到底留住了没有"如实反映到界面。

随后又做了一轮全量审查（四路并行只读子代理：规格 / 约定与气味 / 全库逻辑缺陷 / 死代码与重复），
修掉 10 项：会话线程可能被音频设备卡死（加超时）、主人自己设的 `Ctrl+反引号` 会被迁移悄悄改回
`Ctrl+Win`、钩子回调里仍有文件 I/O、窗口里的"留在了剪贴板"与提示自相矛盾、会话中途失败不留半句、
长回调周期设备会丢尾帧、"结果总留一份"这类结论与界面/托盘不一致等，并删掉重复素材与死代码。

### 1.3.1（2026-09-25）— 快捷键全面自定义 + 开机静默启动 + 全量审查 31 项修复
起因：主人反馈三件事 —— ① 快捷键必须能用 Win 键位、默认要改成 `Ctrl + Win`，但改完仍不生效；
② 开机自启时会弹窗，要求后台静默隐藏；③ 怀疑说话时会"多打一份字"。

第一轮修了①和②，主人复测后①**仍未解决**，于是逐层查根因，发现是三处叠加：配置文件里还是旧默认值
`Ctrl + 反引号`（未自动升级）、egui 把 `Ctrl/Win` 当成主键导致录制在按下修饰键时就中断、录制时修饰键的
记忆被最后一个松手的键覆盖。改法：启动时自动把旧默认值升级为 `Ctrl+Win`（用户自定义的组合原样保留）、
录制时跳过 `Ctrl/Alt/Shift/Win` 只当修饰键、修饰键按"只增不减"记录（任意松手顺序都能录全），
并把所有按键统一走一张总表映射（修掉 `;` 等符号键被写成 `VKBA` 存不下去的毛病）。
开机静默启动靠新增的 `--autostart` 参数实现（eframe 第一帧会强制显示窗口，光"启动时隐藏"挡不住）。
③ 未能复现，但排查后确认服务端二次识别可能重复上报同一句，于是按**句子编号做幂等**（重复编号替换、
旧编号丢弃、迟到的中间结果丢弃）做防御性修复。

随后跑了一轮全量代码审查：32 项问题、修复 31 项（1 项为 Windows 平台限制，如实保留），
其中**严重 7 项**包括：跨线程"打开设置窗"的请求被主循环每帧的隐藏指令盖掉（改成请求位置位 + 重绘，
并在 `logic()` 开头优先消费）、麦克风采集线程的尾帧可能来不及进通道就被丢弃（`stop()` 后等 60ms）、
`EmptyClipboard` 失败时漏掉 `GlobalFree` 的内存泄漏、日志重入导致互锁等。
