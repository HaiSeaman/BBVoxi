# BBVoxi 1.4.1 版本发布说明

> **Release: BBVoxi 1.4.1 — 一键自动更新 · 录音麦克风可选 · 两轮全量审查修复**
> 发布日期：2026-10-07 ｜ 状态：稳定版（Stable） ｜ 上一版本：[1.4.0](./RELEASE_v1.4.0.md) ｜ 版本索引：[版本历史](./版本历史.md)

本文档记录 BBVoxi **1.4.1** 的交付物，包括安装、功能、技术要点、测试结果与已知限制。

本版做三件事：

1. **一键自动更新**（全新功能）：设置窗底部多一个「检查更新」按钮 —— 查到新版本**先弹窗问一句**，
   确认后自动下载、核对 SHA-256 指纹、替换自身并重启。失败时给一个「手动下载」退路。
   国内网络下走 Windows 系统代理，实测比直连**快 10 倍**。
2. **录音麦克风可选**（全新功能）：「通用」页新增「麦克风」下拉栏，列出本机**所有**录音设备；
   选中一台之后录音只用它，**设备不在线时自动回退系统默认设备**并在界面上说明。
3. **两轮全量代码审查与修复**：用 6 路 + 5 路只读审查员按模块深挖，每条结论都由维护者逐行复核后处理，
   共修掉约 **50 项**问题 —— 其中「会丢数据 / 丢密钥 / 麦克风停不下来 / 修饰键卡住」这一类硬伤 **8 条**，
   另有 8 项因证据不足或属设计取舍而**保留并写明原因**（见 [审查报告](./全量审查与修复报告-v1.4.1.md)）。

单元测试 **197 → 239 条全部通过**（本版新增 42 条，另有 7 条手动/真机用例标 `ignore`）。
产物自检：exe 内含界面版本串 **`v1.4.1`**、自动更新相关串（`检查更新` / `手动下载` / `正在下载新版本` /
`api.github.com/repos/` + `HaiSeaman/BBVoxi`）、麦克风选择相关串，且**不含** `v1.4.0` / `v1.3.3` 旧串。

**Windows 端按住即说、边说边出字、松开就输入的语音输入法；本版起按一下按钮就能自己更新。**

## 3. 系统要求

与 1.4.0 完全一致：Windows 10 1809+ / Windows 11，x86_64，普通用户权限，无需运行时。
三家 ASR 服务商与音频规格（16 kHz / 16 bit / mono PCM，自动重采样）无变化。

**新增两条与自动更新有关的要求**：

- 程序要放在**自己能写的目录**里（桌面、D 盘自己的文件夹都行）。放 `C:\Program Files`
  这类受保护目录时，替换自身会被系统拒绝 —— 程序会在下载前就检查并直接说明。
- exe **没有代码签名证书**，更新后第一次运行时 Windows 可能弹"未知发布者"提示。
  这是所有未签名软件的通病，不是更新功能的问题。

## 4. 安装与首次运行

1. **1.4.0 及更早的用户：本版仍需手动下载覆盖**（旧版没有自动更新功能，它不知道自己该更新）。
   用 `BBVoxi-1.4.1.exe` 覆盖旧 exe 即可，配置自动兼容、**本版无需任何迁移**。
2. **从 1.4.1 起，以后升级一键搞定**：设置窗底部 →「检查更新」→ 弹窗点「现在更新」→
   下载完再点「立刻重启」，就是新版本了。
3. 首次运行流程与 1.4.0 相同：填凭据（「语音服务」页）→「测试识别」→ 按需设置「识别选项」→「保存」→ 关窗即最小化到托盘
4. 在任意程序的光标处按住 `Ctrl + Win` 说话，松开即输入
5. 「通用」页现在多了**麦克风选择**（下拉栏 + 「刷新」按钮）

### 6.1 一键自动更新（本版重点一）

| 失败 | 大白话说明原因（超时/解析失败/指纹不符/目录不可写/被杀软占用…）+ 「手动下载」按钮 |

- [x] **先问一句再装**：下载 + 替换自身不可逆，而主人可能正干活
- [x] **不做后台轮询**：只在你点按钮时联网，平时一个字节都不发
- [x] **不做镜像加速**、不写注册表、不装服务

- [x] 「通用」页新增「麦克风」下拉栏，列出本机**所有**能录音的设备（含「系统默认」）
- [x] 「刷新」按钮：插上/拔掉设备后点一下就更新列表；每次打开设置窗也会自动重列一遍

- [x] **设备不在线时自动回退系统默认设备**（不会因为选错设备就录不出声），并在那一行写明"插好后点「刷新」就能继续用"

### 6.3 两轮全量审查修掉的问题（本版重点三，节选）

**会丢数据 / 丢密钥 / 卡住的硬伤：**

| 问题 | 后果 | 修复后 |
|---|---|---|
| 配置文件读不出来时（可能是被临时占用）回退默认值，之后任何写盘操作都会把原文件覆盖成空配置 | **API Key 永久丢失** | 先把原文件另存为 `config.json.bad` 再回退，日志写明怎么恢复 |
| 录音途中改键/保存只清状态、不发停止指令 | 会话只认"松开"，**麦克风停不下来**（普通录音没有时长上限） | 清状态时补发停止指令 |
| 改键捕捉期间无条件吞掉 Win 键的松开 | 外壳以为 Win 一直按着，之后**敲字母就弹 Win+ X** | 只吞"确实由我们接管过"的 Win |
| 「立刻重启」（更新）直接退出进程，不保存 | 有未保存改动时**改动被无声丢掉** | 先拦一句"先点保存再重启" |
| 更新失败后状态永久霸占底部反馈条 | 之后所有提示都看不见 | 失败只用会自然退场的那条状态消息说 |
| 音频回调线程里写日志（抢全局锁 + 写文件） | 磁盘一忙就卡住回调，**直接丢音** | 回调只置标志，由采集线程写日志 |
| 千问/腾讯把服务端"掐断连接"当成正常收尾 | 误报"没有识别到内容，请靠近麦克风再说一次" | 如实报关闭码与原因（三家共用一套判断） |
| 更新接班实例等不到单实例锁时"没锁继续跑" | 之后双击 exe 会跑出**两个托盘、两个键盘钩子** | 等不到就退出并唤醒老实例 |

**其他修复（共约 50 项，完整清单见审查报告）：**

- 配置**升级会重复跑旧步骤**（1.3.x 用户升级时，自己关掉的开关被强行打开、自己设的快捷键被改回去）
- 「不保存」其实一样都没丢（被丢弃的改动下次打开设置窗又回来，再点保存就一起落盘）
- 收尾"把剩余音频发完"最坏能卡 **100 秒**（现在整段 2 秒预算）
- 麦克风出错时若"松开快捷键"抢先一步，错误原因被丢掉 → 误报"没有识别到内容"
- 剪贴板读不出来时被当成"剪贴板是空的"（误报"可能被其他程序改写"）
- 粘贴兜底写完不回读（可能把**别人的文字**打进光标处，并记假账 → 下次修正会删掉主人自己打的字）
- 粘贴/补发 Win 时系统只吃下一半事件 → **Ctrl 或 Win 卡住**（失败后补一次"松开所有修饰键"）
- 托盘图标没建好时也在记账 → 托盘建好后一直显示"就绪"
- 豆包收到空 `utterances` 数组会**吞掉整帧文本**；ASR 通道满时会连**服务端关闭帧**一起丢
- 更新相关的：版本比较只取前三段（`1.5.0.1` 会被当成 `1.5.0`，更新永远说"已是最新"）、
  下载临时文件名直接拼 GitHub tag、更新线程异常退出会让按钮永远灰着、`.new.exe` 残留
- 界面：底栏加第 5 个按钮后版本号被挤出窗口；版本号挪到左下角显示

## 7. 技术亮点

### 7.1 自动更新：为什么是"自己写薄薄一层"

| 方案 | 结论 |
|---|---|
| **自己写 + 官方 GitHub 接口** | ✅ 采用 —— 发布形态就是**单个 exe**，不需要安装包格式；代码约 300 行，中文提示可控 |
| `self_update` crate 的高层接口 | ❌ 它要求 release 资产是**压缩包**，用它就得改成"每次发版先打 zip"（它的底层工具 `self-replace` 本版已在用） |
| Tauri Updater | ❌ 那是 Tauri 框架的插件，本项目是 eframe/egui |
| WinSparkle / MSIX / winget | ❌ 要额外分发 DLL、写 appcast、配签名、走商店流程；对个人小工具是过度工程，而且没有代码签名证书照样会弹"未知发布者" |

依赖只加了三个小库：`ureq`（联网，钉在 `~3.2` —— 3.3 起要求 rustc ≥1.85，会破坏本仓库"Rust 1.80+ 能编"的承诺）、
`sha2`（核对指纹）、`self-replace`（安全替换正在运行的自己）。

### 7.2 一个决定性发现：系统代理

| 下载方式 | 实测速度 | 下完 8.4 MB |
|---|---|---|
| 直连 GitHub | 68 KB/s | 约 2 分钟（还会中途卡死：600 秒都没下完 1 MB） |
| 走本机系统代理（`127.0.0.1:10808`） | **663 KB/s** | **约 13 秒** |

`ureq` 默认**不读** Windows「Internet 选项 → 代理服务器」，所以特意开了 `win-system-proxy` 特性；
并加了兜底：**代理软件关了、系统设置还开着**时自动退回直连（慢，但总比更新不了强）。

### 7.3 Windows 上替换"正在运行的自己"

Windows 不允许覆盖运行中的 exe。标准姿势是三步：**旧文件改名让位 → 新文件原子就位 → 本进程退出后删掉旧文件**，
交给成熟的 `self-replace` 做（它靠一个"main 之前"的钩子完成收尾，不会多起一个托盘实例）。
它要求程序所在目录**可写** —— 所以下载前先做一次预检，写不进去就直接告诉主人换目录。

### 7.4 麦克风选择：存编号不存名字

下拉栏显示 Windows 那个好认的名字，配置里存的却是**设备端点编号**（形如 `wasapi:{0.0.1.…}.{guid}`）：
两台同型号麦克风名字完全一样，只存名字会出现"选的是它、开的却是另一台"。
编号跨重启、跨插拔都不变；设备被拔掉时按"编号找不到"判定 → 回退系统默认 + 界面提醒。

### 7.5 这一轮审查怎么做的

按两条轴分开审（**需求/正确性** 与 **规范/一致性**），6 路只读审查员按模块深挖（audio+session、ui、
update+main、asr 四文件、注入三文件、config+hotkey+autostart+log），**每条结论都由维护者自己读代码复核**
之后才动手 —— 其中 2 条经核实**不成立**（README 那条"记一次日志"其实是两条不同的通道；测试代码重复属设计取舍），
另有 8 项因需要真帧/真机证据而**明确保留**。

## 11. 已知问题与限制

1. **本版是自动更新的"起点"，不是"验收"**：1.4.0 及更早的用户没有更新功能，这次仍要**手动下载覆盖**。
   真正的端到端验收要等你发**下一个版本**（1.4.2 或更高）时，用 1.4.1 点一次「检查更新」才算跑通。
   这一步替换自身 + 重启没法在自动化测试里做（会把测试进程换掉），已在测试矩阵里如实标注。
2. **exe 未签名** → 更新后第一次运行可能弹"未知发布者"（买代码签名证书才能消除）。
3. 程序必须放在**自己能写的目录**，否则替换会被系统拒绝（下载前会预检并说明）。
4. **更新后文件名不变**：你双击的 `BBVoxi-1.4.1.exe` 里装的会是新版内容（内容变了、名字没变）。
5. 国内网络下更新速度取决于系统代理是否可用；不可用时会自动直连，但会**慢很多**（实测 68 KB/s）。
6. 以下问题**已知但本版未改**（需要真帧或真机证据，详见审查报告）：
   腾讯云的服务端句序（`result.index`）是否可用于去重、豆包"定稿翻回未定稿"的真实行为、
   千问 `sentence_id` 的单调性假设、服务端关闭码 1000 之外是否也代表正常收尾、
   开机自启在"快速启动"机器上的判定。
7. 其余限制沿用 1.4.0（管理员窗口无法注入、录音途中切窗口不自动输入、剪贴板只保得住文本、
   腾讯 60 秒引擎上限、内存占用约 114 MB 等）。

## 12. 升级指南（从 1.4.0 升级）

1. 下载 `BBVoxi-1.4.1.exe`，**覆盖**旧的 exe（配置自动兼容，**本版不需要任何迁移**）。
2. 打开设置窗确认左下角显示 `v1.4.1`。
3. 「通用」页看一眼「麦克风」：默认是「系统默认」（跟随 Windows），想让录音固定用某台设备就选它。
4. 以后升级：点底部「检查更新」即可（本版起才有这个能力）。
5. 想回到旧版：直接把旧的 exe 覆盖回来（配置一直是向后兼容的）。
