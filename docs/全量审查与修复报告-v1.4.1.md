# BBVoxi 1.4.1 全量审查与修复报告

> 对应版本：[1.4.1](./RELEASE_v1.4.1.md) ｜ 上一份报告：[全量审查与修复报告 v1.4](./全量审查与修复报告-v1.4.md) ｜ 版本索引：[版本历史](./版本历史.md)
>
> 本报告记录 1.4.1 开发期间**两轮全量代码审查**的发现、处理与验证：
> 第一轮发生在「麦克风可选」功能之后，第二轮是在「自动更新」功能之后（按 `/code-review` 流程的两条轴做的）。
> 共修掉约 **50 项**问题，另有 **8 项**因证据不足或属设计取舍**保留并写明原因**。

---

## 1. 审查方法

- **两条轴分开**：「需求/正确性」（功能是否真的按宣称工作、有没有 BUG）与「规范/一致性」
  （是否符合本仓库自己的约定、有没有通用代码坏味道）。分开是为了让一条轴的问题不会掩盖另一条。
- **11 路只读审查员**：第一轮 5 路（audio+session / ui / asr 四文件 / 注入三文件 / config+hotkey+autostart+log），
  第二轮 6 路（同上并追加 update+main）。审查员**只读**：不改文件、不跑 cargo、不碰网络与注册表。
- **每条结论都自己复核**：审查员报的每一条，都由维护者重新读代码确认后才动手。**其中 2 条经核实不成立**，已剔除：
  1. "README 说『音频缓冲满记一次日志』与代码不符" —— 核实是**两条不同的通道**（音频缓冲确实只记一次；
     ASR 帧通道是首条 + 每 64 条），README 描述的对象没错。
  2. "测试代码重复、`Provider` 三处 match" —— 判断为设计取舍（为 3 个服务商引入多态属于过度工程），不改。
- **不做 GUI 测试**（项目铁律）：界面相关的结论一律用**无界面渲染快照**（真实字体、真实布局）量出来。

## 4. 明确保留、未修改的（8 项 + 原因）

| 项 | 为什么不动 |
|---|---|
| 腾讯云用官方 `result.index` 做去重 | 仓库内**两份文档互相矛盾**（代码注释说"协议没有句子编号"，旧报告说有 `index`）。改动会影响"同一句会不会重复上屏 / 丢字"，**必须拿到真帧**才能定 |
| 豆包"迟到中间结果"守卫对它无效 | 需要真帧证明 `definite` 会从 true 翻回 false；否则改了会把正常中间结果整段丢掉（后果更糟） |
| 千问 `sentence_id` 的单调性假设 | 需要真帧（同句是否共用 id、是否回绕） |
| `Close(1000)` 之外是否也算正常收尾 | 需要三家真帧；现在的行为是"宁可报出来" |
| 帧通道满时丢帧不提示主人"结果可能不完整" | 要新增面向主人的文案（属新功能，等主人发话） |
| 开机自启在"快速启动"机器上的判定 | 需要一台开了快速启动的电脑实测（本机 `HiberbootEnabled=0`，复现不了） |
| `\t` 算不算退格单元 | 不同程序里 Tab 有的插入字符、有的只移焦点，改哪边都会错一半；而识别结果里不会出现制表符 |
| 同一进程两条写配置路径共用 `config.<pid>.tmp`、`Provider` 三处 match、版本号用 String 传递 | 属设计取舍 / 将来隐患（当前无并发场景）；改它们是过度工程 |
