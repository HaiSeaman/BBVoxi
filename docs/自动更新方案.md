# 自动更新方案（设置窗「检查更新」按钮）

> **状态：已在 v1.4.1 实现并发布**（实现文件 `src/update.rs` + `src/ui.rs` 的按钮与弹窗 + `src/main.rs` 的接班逻辑）。
> 发布说明见 [RELEASE_v1.4.1.md](./RELEASE_v1.4.1.md)，本轮审查与修复见 [全量审查与修复报告-v1.4.1.md](./全量审查与修复报告-v1.4.1.md)。
>
> 目标：主人在 GitHub 发布新版本后，老版本的用户**点一下按钮**就能自动下载、安装并重启，
> 不需要自己去网页找安装包。
> 位置：设置窗底部按钮行的「项目地址」右边。

---

## 一、选型：为什么是"自己写薄薄一层 + 官方 GitHub 接口"

| 方案 | 结论 | 原因 |
|---|---|---|
| **自己写（本方案）** | ✅ 采用 | 主人的发布形态就是**单个 exe**（Releases 里就一个 `BBVoxi-x.y.z.exe`），不需要安装包格式；代码约 300 行，中文提示可控，出错原因能如实说给主人 |
| `self_update` crate 的高层"一键更新" | ❌ | 它的 `update()` 要求 release 资产是**压缩包**（zip/tar.gz），用它就得改成"每次发版先打包 zip"，否则只能退回来自己写（等于本方案多套一层皮）。它的底层工具（`self-replace`）我们**已经在用** |
| Tauri Updater | ❌ | 那是 Tauri 框架的插件，本项目是 eframe/egui，不是 Tauri |
| WinSparkle / MSIX / winget | ❌ | 要额外分发 DLL、写 appcast.xml、配 DSA/EdDSA 签名、走安装包与商店流程；对个人小工具是明显的过度工程，而且**没有代码签名证书照样会有"未知发布者"提示**，收益和本方案一样 |

依赖只加了三个（都很小）：

| 依赖 | 用途 | 备注 |
|---|---|---|
| `ureq`（`~3.2` + rustls + **win-system-proxy**） | HTTPS 请求（带重定向、超时） | 版本钉在 3.2：3.3 起要求 rustc ≥1.85，而本项目承诺"Rust 1.80+ 能编" |
| `sha2` | 核对下载文件的 SHA-256 | GitHub 每个发布资产都公布了这个指纹 |
| `self-replace` | 替换**正在运行**的自己 | Windows 不许覆盖运行中的 exe，它按标准姿势做"旧文件改名让位 → 新文件原子就位 → 本进程退出后删掉旧的" |

## 二、最关键的一个发现：系统代理

排障时实测出来的，**没有它这个功能等于废的**：

| 下载方式 | 实测速度 | 下完 8.4MB 需要 |
|---|---|---|
| 直连 GitHub（不经代理） | 68 KB/s | 约 2 分钟（还会中途卡死：600 秒都没下完 1MB） |
| 走本机系统代理（`127.0.0.1:10808`） | **663 KB/s** | **约 13 秒** |

`ureq` 默认**不读** Windows「Internet 选项 → 代理服务器」那个设置，所以必须开
`win-system-proxy` 特性。开了之后本机实测：查版本 + 下载 8.4MB + 核对指纹 = **13.6 秒**。

另外还加了兜底：**代理软件关掉、系统设置还开着**时请求会连不上，所以策略是
"先走系统代理，失败再退回直连"（直连慢，但总好过更新不了）。
这条路径有单独的测试（用一个"死代理"`127.0.0.1:9` 演出来）。

## 三、实现

### 流程（主人选的"先问一句再装"）

```
点「检查更新」
   ↓ 后台线程：GET api.github.com/.../releases/latest
   ├─ 线上不比本机新 → 底部反馈条："已是最新版本（v1.4.0）"
   └─ 有新版本 → 弹窗「发现新版本 v1.5.0」+ 更新说明 + 【取消】【现在更新】
                       ↓ 点【现在更新】
        后台线程：下载 exe → 边下边报进度（底部显示"正在下载 42%（3.5/8.0 MB）"）
                       ↓
        核对 SHA-256（GitHub 公布的 digest；对不上就删掉并报错）
                       ↓
        self-replace 替换自身（要求程序目录可写，替换前已预检）
                       ↓
        弹窗「更新已装好，重启后生效」+ 【稍后】【立刻重启】
                       ↓
        点【立刻重启】→ 起新进程（带 --updated --settings）→ 本进程收尾退出
```

### 关键设计点

- **不在界面线程联网**：查版本和下载都在独立线程里跑，靠 `std::sync::mpsc` 把
  「查到 / 进度 / 装好 / 失败」回给界面（`UpdateMsg`），界面每帧收一次。
- **`--updated` 参数**：新实例必须跳过单实例检查（老进程还在退出路上，锁没松），
  否则新实例会以为"已经有人在跑"、发个唤醒消息就自杀 —— 现象是"点了重启什么都没发生"。
  但新实例**必须等老进程松锁再拿锁**（`single_instance_lock_waiting`）：不拿锁的话，
  老进程退出后主人再双击一次 exe，那个进程会以为自己是第一个实例，跑出两套（双托盘、双钩子）。
- **退出走 `main`**：托盘图标必须先析构再 `process::exit`（否则图标残留在托盘），
  这套收尾只有 `main` 有，所以界面只负责"起新进程"，然后交回请求。
- **下载的临时文件放在 exe 同目录**（`BBVoxi-<版本>.new.exe`）：`self-replace` 靠
  `rename` 就位，跨盘会失败。装好或失败后都会清掉，不留垃圾。
- **更新说明按字符截断**（400 字），按字节切中文会切出乱码。

### 出错时怎么办（每种都给大白话原因 + 「手动下载」按钮）

| 情况 | 主人看到的话 |
|---|---|
| 网络不通 / 超时 | 「等待超时（global；网络太慢或被拦）」+ 提示走手动下载 |
| 域名解析不了 | 「连不上 github.com（域名解析不了，检查网络/DNS）」 |
| 仓库/版本不存在 | 「GitHub 上找不到这个仓库或还没有发布版本（404）」 |
| 指纹对不上 | 「下载下来的文件和 GitHub 公布的指纹对不上，已删除（期望 …，实际 …）」 |
| 程序目录不能写 | 「程序所在目录不能写（…）：请把 BBVoxi 放到你自己能写的目录再更新」 |
| 替换被杀软占用 | 「替换程序文件失败（可能被杀软/别的程序占用，或目录没有写权限）」 |

## 四、验证证据（都是真跑出来的）

| 验证 | 结果 |
|---|---|
| 单元测试 | **228 条全绿**（新增 15 条：版本比较、GitHub 返回解析、指纹解析、SHA-256 标准向量、进度换算、状态机、底栏排版） |
| 拉真实发布数据 | 通过（`1.4.0`、`BBVoxi-1.4.0.exe`、`sha256:bdf2a709…`、2875 字说明） |
| **真机真下载 + 指纹核对** | 通过：8,394,752 字节，**13.6 秒**，SHA-256 与 GitHub 公布值一致，测试后自动删除 |
| 代理不可用的兜底 | 通过：死代理失败 → 直连成功查到版本 |
| 底栏排版（580 与 520 两种窗口宽度） | 通过：「检查更新」按钮在、版本号没被挤出窗口 |
| 麦克风功能回归 | 通过（列设备/选设备/回退默认仍正常） |
| 发布版编译 | 见 `target/release/bbvoxi.exe`（零告警） |

**没能自动验证的一步（如实说明）**：`self-replace` 替换自身 + 重启，**不能在测试里跑**
（那会把正在跑测试的进程换掉）。这一步只能等主人真的发一个更高版本时点一次按钮，
才算最终验收。它用的是成熟库（`self-replace` 被 cargo-dist 等广泛使用），
且替换前的每一步（目录可写、指纹核对）都已经先验证过。

顺带抓到的两个 bug（写测试时抓出来的）：

1. 版本比较把"预发布版"符号写反了：`1.5.0-rc` 被判成比 `1.5.0` 还新；
2. 底栏加第四个按钮后，窄窗口（520）下版本号会被挤出窗口。

## 五、发版流程（主人每次发新版照这个来）

1. 改 `Cargo.toml` 里的 `version`（例：`1.5.0`）—— **不能忘**：界面版本号、更新比较基准都用它。
2. `cargo build --release` → 把 `target\release\bbvoxi.exe` 改名成 `BBVoxi-1.5.0.exe`。
3. GitHub 上建 Release，**tag 写版本号**（`1.5.0` 或 `v1.5.0` 都认），把 exe 传上去。

不需要额外维护版本清单文件 —— 一切都从 GitHub 的 Releases 接口读。

## 六、没做 / 以后想做再说

- 不做后台自动轮询（只在你点按钮时联网）、不做增量更新、不做镜像加速、不碰注册表。
- 更新后**文件名不变**（你双击的 `BBVoxi-1.4.0.exe` 里装的会是 1.5.0 的内容）。
  想让文件名也跟着变，需要在替换后再加一步"改名 + 再重启"，主人说一声再做。
- 想彻底去掉"未知发布者"提示，只能买代码签名证书（本方案无法绕过）。
