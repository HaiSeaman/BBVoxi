## 2. 一句话定位

**Windows 端按住即说、边说边出字、松开就输入的语音输入法。**
本版在保持"常驻托盘轻量原生应用"定位不变的前提下，加固代码质量、重修设置界面。

## 4. 安装与首次运行

1. 把 `BBVoxi-1.1.exe` 放到任意目录（推荐 `%LOCALAPPDATA%\BBVoxi\`）
2. 双击运行：右下角出现 BBVoxi 托盘图标（已有旧版在运行则直接唤醒并弹出设置窗）
3. 右键托盘 → "设置"（或再次双击 exe），填入 ASR 服务商与 API Key
4. 设置里点「测试识别（5 秒）」——看到能出字即可使用
5. 任意前台窗口下，按住快捷键说话，松开即输入

- **卸载**：直接删除 exe；配置与日志保留在 `%APPDATA%\BBVoxi\`
- 可选"开机自启"通过注册表 `HKCU\...\CurrentVersion\Run` 实现（本版起写在"通用"卡片里）

## 7. 技术亮点（本版修复的原理）

### 7.1 裸按键 keyup 不再被吞（修复"按键卡住"）
**背景**：全局钩子命中组合键时需吞键（避免 `Ctrl+1` 触发浏览器切标签）。1.0 无条件吞触发键 keyup，
当用户**没按修饰键**、裸按触发键（如只按 `1`）时 keydown 已放行给前台程序，keyup 却被吞掉，
在跟踪 keyup 的程序里表现成"按键一直按着"。

**修复**（`src/hotkey.rs`）：判定状态从 `armed`（正在按住说话）拆出新增 **`held`**（本次触发键的
keydown 是否被我们吞过）。keyup 只吞 `held` 的键：
- 正常录音：按住-松开都吞 → 行为不变
- 裸按触发键：keydown/keyup 都放行 → 修复卡住
- 先松修饰键结束录音后，触发键 keyup 仍吞（keydown 从未到过前台）

新增回归测试 `bare_trigger_keyup_passes_through` 与 `releasing_modifier_first_still_stops` 锁定该行为。

### 7.2 "识别开关"真正接线（修复摆设开关）
- **千问**：请求参数新增 `semantic_punctuation_enabled`（跟随「自动添加标点」），此前完全没传
- **腾讯云**：`filter_modal` 由写死 `0` 改为跟随「口语顺滑」开关
- **UI 联动**：`Provider × 设置项` 能力矩阵写入界面，不支持项 `add_enabled(false)` + 说明文案

### 7.3 跨实例唤醒（新增）
利用 Windows 命名事件：首个实例创建 `BBVoxi_ShowSettings` 事件并在 `logic()` 10Hz 轮询；
第二实例发现单实例互斥量已存在 → `SetEvent` 置位后立即退出。自动复位事件保证"一次唤醒只弹一次窗"。

### 7.4 DPI 说明（刻意不改，防止将来误修）
`window_geometry()` 在 eframe 初始化前执行，进程此时仍是 DPI-unaware，
`GetSystemMetrics` 返回的即为 96dpi 虚拟化逻辑坐标，与 egui 逻辑坐标一致——125%/150% 缩放屏上
居中位置依然正确。已加注释说明"不要顺手修"。
