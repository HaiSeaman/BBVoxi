## 二、发现的缺陷与修复

### 【严重】S1 · 注入失败后整段结果被静默丢弃

**现象**：目标程序拒绝逐字注入（管理员权限窗口、部分特殊程序）之后，主人说的话**既不进目标程序，也不进剪贴板**，界面上只留一句错误，内容永远消失。

**根因**：`LiveTyper::finish` 走的是 `plan(self.blocked(), ...)`，而 `blocked()` 的定义里**包含 `failure.is_some()`** —— 一旦某一步注入失败过，`plan` 就返回 `None`，`finish` 于是返回一个"什么都没做"的 `Ok`。而调用方 `session::run_session` 恰恰是靠 `Err` 才执行 `hand_off_to_clipboard`（把结果放进剪贴板）：

```rust
// 修复前：失败态被 blocked() 吃掉，返回假的 Ok
match plan(self.blocked(), &self.sent, desired) {
    Some(planned) => self.execute(planned, desired),
    None => Ok(()),          // ← 结果在这里消失
}
```

**改法**：`finish` 开头显式检查失败状态并抛出原因，让 `Err` 真正到达调用方：

```rust
if let Some(reason) = &self.failure {
    return Err(anyhow!("{reason}"));
}
```

**验证**：新增 `finish_reports_a_latched_failure_so_the_caller_can_use_the_clipboard`（构造失败态 → 断言必抛 `Err`、错误文本带原因、且未注入任何字符）。
**变异检查**：把该判断临时改成 `self.failure.as_ref().filter(|_| false)` → 测试**立刻红**；改回 → 全绿。证明这条测试真的在守这个行为。

### 【中等】M1 · 切走窗口后"一次性放弃、永不复位"

**现象**：主人切出去看一眼再切回来，本次整段识别结果就不出现了（正是主人反馈的"字没显示在光标处"的一种）。

**根因**：`LiveTyper` 里有个 `abandoned` 标志，切走时置位且**永不复位**；而它是 `blocked()` 的输入之一。

**改法**：重命名为 `away`，语义改为"此刻是否不在原窗口"，`guard()` 每次都重新判定（切回来自动恢复）。日志同步改为"暂停 / 恢复"两句。
**为什么切回来是安全的**：`sent` 记的是打在**原窗口**里的字，回到原窗口继续差分完全正确；真正危险的只有"往**别的**窗口写字或退格"。

**验证**：`returning_to_the_original_window_resumes_typing`（切走 → 断言暂停且 blocked → 切回 → 断言恢复且 `sent` 未被污染）。

---

### 【中等】M2 · 改键捕捉的 `paused` 锁存 → 全局快捷键永久失效

**现象**：在设置里点「重新录制」进捕捉状态，然后把设置窗关掉（收起窗口 = 最小化到托盘），此后**按任何快捷键都没反应**，且无任何提示。

**根因**：捕捉期间键盘钩子是**暂停**的（`paused = true`，让按键原样交给窗口）。而 eframe 0.35 在窗口隐藏后**不再调用 `ui()`**（`logic()` 照常 10Hz 跑）。于是"结束捕捉"这段代码（原本在 `ui()` 路径上）永远不会执行，`paused` 永远停在 true。

**改法**：不去逐个补"隐藏窗口"的调用点（已知就有两条，将来还会有第三条），而是判真正的不变量 —— **捕捉只能在设置界面正在被绘制时存在**：

- `ui()` 每次绘制刷新心跳 `painted_at`
- `logic()` 里 `reap_capture_if_ui_gone()`：心跳超过 `CAPTURE_IDLE_LIMIT`（400ms，4 倍帧间隔余量）就自动结束捕捉
- 判据抽成纯函数 `capture_is_stale(capturing, idle)` 以便单测

**验证**：`capture_expires_only_when_capturing_and_past_the_limit`（4 断言：没在捕捉不动作 / 刚画过不误杀 / 刚好到边界不算 / 超过必须收掉）。

---

### 【中等】M3 · 剪贴板写入顺序错误，可能先清空后失败

**现象**：写剪贴板失败时，主人原来复制的**内容已经被清空**，且不可恢复。

**根因**：`write_text` 先 `EmptyClipboard()` 再 `GlobalAlloc` + 填充。一旦后面的分配或锁定失败，剪贴板已经空了 —— 把一次"写入失败"放大成"数据丢失"。

**改法**：调整顺序为 **先备好新内容（分配 + 填充 + 解锁）→ 最后才 `EmptyClipboard()` → `SetClipboardData()`**。所有失败路径都在清空之前。

**验证**：`roundtrip_through_the_real_clipboard`（`#[ignore]`，手动跑过真剪贴板往返）；纯函数侧 4 条（UTF-16 NUL 结尾、代理对完整、空串仍有终止符、字节数与分配一致）。

---

### 【中等】M4 · 目标窗口记录存在竞态（可能一个字都打不出去）

**现象**：偶发 —— 本次录音的结果一个字都没输入，日志说"主人切到了别的窗口"，但主人其实一直没动。

**根因**：`hide_settings()` 只是把"隐藏"请求投给 egui，**并不保证焦点立刻离开本程序**。旧代码紧接着就取前台窗口，于是可能取到**我们自己的窗口句柄**；接下来第一次 `guard()` 就把主人的应用当成"中途切过来的窗口"。

**改法**：新增 `wait_for_foreign_foreground()` —— 最多轮询 25 次（750ms），等到前台窗口**确实不属于本进程**再记为本次的目标窗口；等不到就返回 `None`（句柄未知时不做切换判定，宁可"不设防"也不"乱设防"）。测试模式不取（它一个字都不注入，此刻窗口本来就该在最前面）。

---

### 【中等】M5 · 收尾期间不消费按键 → "幽灵会话"顶掉刚出的结果

**现象**：松开快捷键立刻又按一次，会先弹一句"没有识别到内容"，把刚显示出来的识别结果从界面上顶掉。

**根因**：等最终结果的那段循环（最长 8 秒）只等 ASR 消息，**不读命令通道**。期间按下的 `Cmd::Start/Stop` 会留在队列里，等本次会话结束后立刻启动一个**录到 0 音频**的新会话。

**改法**：收尾循环改为 `select!`，同时消费命令：`Start/Stop` 记一条日志后丢弃（此时麦克风已释放，确实录不到内容）；`Test` 单独回一句"上一次识别还没结束，请稍后再点「测试识别」"（按钮按下去毫无反应比报错更让人困惑）。

## 三、明确决定**不修**的项目（坏气味）

以下四条是审查中识别出的结构性问题，**本版不动**，理由一致：纯结构改动、零行为收益，且前两条要动的是"服务商切换"这条主链路。

| 坏气味 | 位置 | 现状 |
|---|---|---|
| Repeated Switches（重复的条件分支） | `Provider` 的 match 级联横跨 `config.rs` / `asr/mod.rs` / `ui.rs` 三文件 10 余处 | 新增服务商要改多处，但改动点集中且都被测试覆盖 |
| Divergent Change（一处文件因多个无关原因被改） | `ui.rs` 同时承担 `ShellExecuteW` 调用与 egui→虚拟键码映射 | 拆分收益不抵风险 |
| Primitive Obsession（原始类型替代领域概念） | `text_field` / `secret_field` 用裸字符串当控件 id | 无实际缺陷 |
| Data Clumps（成组出现的字段） | `Hotkey` / `Mods` 的数据簇 | 已足够清晰 |

> 若后续要开这四条，建议**独立一轮**做（只动结构、不改行为），与本轮的"修缺陷"分开提交，便于回溯。

## 四、诚实的验证缺口

以下两处修复**没有自动化测试**，原因是它们需要真实的运行时环境：

1. **M4（`watch` 竞态）与 M5（幽灵会话）**：要触发必须有一个真实的 ASR 会话（联网 + 麦克风 + 凭据），项目约定不做 GUI/实机自动化测试；

## 六、过程中出现的问题（含自身失误，如实记录）

1. **`matches!` 宏不能带消息参数**：写成 `assert!(matches!(x, Y), "…")` 会在宏展开处报 `no rules expected ...`。改为先 `let v = …;` 再断言。
2. **一次编辑误删了 `SettingsApp` 的 `edit: Config` 字段**：把结构体首行连字段一起替换掉了，自查时发现并立即补回。
3. **`autostart.rs` 的第一次"修复"是假的**：只加了说明顺序的注释，代码顺序**没动**，句柄照样泄漏。重写为真正的顺序调整后才算修好 —— 教训：注释不等于修复，改完必须回头看代码本身。
4. **新增测试差点污染主人的终端**：`LiveTyper::new(false, Some(100))` 的用例 `blocked()` 为假，会真的走 `SendInput` 往**当前前台窗口**（跑测试时就是终端）打字。删除该用例，并在 `typer.rs` 的 `mod tests` 顶部立下约定：**用例不允许真的走到 `injector`**。
