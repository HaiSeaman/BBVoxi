# BBVoxi 1.4.0 版本发布说明

> **Release: BBVoxi 1.4.0 — 设置界面页签化 · 千问升级 3.1 · 个人词典与识别语言 · 全仓库清理**
> 发布日期：2026-10-07 ｜ 状态：稳定版（Stable） ｜ 上一版本：[1.3.3](./RELEASE_v1.3.3.md) ｜ 版本索引：[版本历史](./版本历史.md)

本文档记录 BBVoxi **1.4.0** 的交付物，包括安装、功能、技术要点、测试结果与已知限制。

本版做三件事：

1. **设置界面页签化**：从"单张长卡片 + 说明全塞悬停气泡"改成**顶部三页签**（语音服务 / 识别选项 / 通用），
   每行是"标题 + 一句说明 + 右侧控件"的紧凑行卡；窗口加宽到 580；新增**三种主题**（跟随系统 / 浅色 / 深色），点了立即生效并落盘。
2. **三家能力补齐**：千问默认模型升级到 **3.1**（近场 VAD + 去语气词接通 + 老配置自动迁移，配置版本 2 → 3）；
   新增**个人词典（热词）**与**识别语言**（豆包 / 腾讯 / 千问各自适配）。
3. **全仓库代码审查与清理**：`cargo clippy` 15 个告警清零，删掉死代码与死字段，清掉无用目录与历史临时产物，
   逐个核实依赖与 windows feature（**无死依赖**）。

单元测试 **190 → 197 条全部通过**（本版新增/改写 7 条）。产物自检：exe 内含 **`v1.4.0`**、
不含旧串 `v1.3.3`、且含千问 3.1 模型串。

## 2. 一句话定位

**Windows 端按住即说、边说边出字、松开就输入的语音输入法。**
本版把设置界面重做成**页签式**（并支持三种主题），把**千问升级到 3.1**、
新增**个人词典（热词）**与**识别语言**两项实用能力，并做了一轮**全仓库代码审查与清理**。

---

## 3. 系统要求

与 1.3.3 完全一致：Windows 10 1809+ / Windows 11，x86_64，普通用户权限，无需运行时。
三家 ASR 服务商与音频规格（16 kHz / 16 bit / mono PCM，自动重采样）也无变化。

## 4. 安装与首次运行

1. 用 `BBVoxi-1.4.0.exe` **覆盖**旧版 exe（配置自动兼容，**本版有一次性迁移**，见第 12 节）
2. 打开设置窗，界面已换新：顶部三页签「语音服务 / 识别选项 / 通用」，每行「标题 + 说明 + 右侧控件」
3. 填凭据（「语音服务」页）→ 「测试识别」→ 按需设置「识别选项」→ 「保存」→ 关窗即最小化到托盘
4. 在任意程序的光标处按住 `Ctrl + Win` 说话，松开即输入
5. 「通用」页可以改快捷键、开机自启和**界面主题**（跟随系统 / 浅色 / 深色）

## 7. 技术亮点

### 7.1 为什么豆包"选语言"要连端点一起切

豆包官方的 `language` 参数**只在整句端点（`bigmodel_nostream`）生效**，实时端点不认。
如果只传参数不切端点，参数会被静默忽略 —— 主人选了"日语"却仍在用中英模型。
所以本版把两件事绑在一起：`request_spec` 选端点、`Doubao::new` 选 `StreamMode`，
**两处用同一个判定条件**（`options.language != "auto"`），改一处必须改两处，靠注释互相指认。
代价是选定语言后出字比「自动」晚一两秒（整句模式要等说完一句）—— 这条写进了界面提示与已知限制。

### 7.2 为什么主题切换要"单独走一趟"落盘

主题是"点了就该立刻见效"的小改动，但它落盘时**不能把编辑中的整份配置写进文件**：
主人可能填了半截 API Key 还没点保存、快捷键可能还没通过校验 —— 顺手存进去就是"没保存的脏数据被偷偷落盘"。
所以切主题时写的是"**上一次成功保存的配置 + 新主题**"，与编辑缓冲区解耦。

### 7.3 为什么千问的模型迁移要"精确匹配旧默认值"

沿用快捷键迁移的教训（1.3.2 那次的回归 bug）：迁移**只能认"从没动过"的旧默认值**，
且**只看升版本这一次**。本次迁移严格做字符串精确匹配 —— 主人自己填过的模型名（哪怕叫
`fun-asr-realtime`、哪怕只差一个字符）**一个字都不动**。

### 7.4 界面改动怎么"不开窗"验收

本工程不做 GUI 测试（慢、不稳、还量不到坐标）。界面改动靠一套**无窗口布局探针**：
用 headless 的 egui 上下文跑**同一份 `SettingsApp::ui`**，把这一帧真实的绘制指令（矩形与文字）抓出来量尺寸。
本版把三页签纳入常驻回归：`content_is_compact`（**每页内容总高 ≤ 600px 且恰好 1 张卡片** ——
所以「个人词典」放进了「语音服务」页而不是塞进「识别选项」页，两页一起量才能过）、
`no_text_overflows_the_window`（两种窗口尺寸、全部页签，任何文字都不许被挤出窗口）等。

### 7.5 为什么"重复的 Backend match"不抽 trait

审查确实发现 `Backend` 的 5 个方法各有一段"match 三家"的重复形状（Repeated Switches 气味）。
但三家的调用签名互不相同（豆包的启动帧要 gzip 压缩、返回 `Result`；腾讯没有启动帧；千问要 `task_id`），
抽成统一 trait 需要引入适配层与错误归一，反而增加间接层与出错面。
对一个"个人小工具"而言，5 段短 match 比一层抽象更好维护 —— 这是**有意保留**，并写进审查报告。

## 11. 已知问题与限制

**与上一版相同的限制（未变化）**

- 目标窗口以**管理员权限**运行时无法输入（Windows UIPI 限制），会给出明确提示。**剪贴板兜底也救不了它**：
  `Ctrl+V` 走的同样是 `SendInput`，一样被拦 —— 但结果仍会复制到剪贴板，粘到普通权限窗口里就行
- 极少数程序会"**假装收下了**"我们的输入：Windows 没有通用接口能查证（实测 Chrome 连插入符都不报告），
  所以不做"检测到没进去就自动再粘一次"——「总留一份」就是为这种情况准备的
- **录音途中切走窗口 → 结果不自动输入，改放进剪贴板**：这是"不打错地方"的安全设计
- 含 `Win` + 普通主键的组合会被系统抢先响应（截图、锁屏等）——Windows 保留键的既定行为
- **开启"留一份"会顶掉你原来复制的剪贴板内容**（可以在设置里关掉）
- 剪贴板只能保住**文本**：原来复制的是图片或文件时无法还原（系统机制限制）
- 腾讯 `Hy-ASR-3.0-preview` 引擎 60 秒上限；豆包「高精度」模式下实时输入看不到逐字上屏

**本版新增的能力限制（如实说明）**

- **腾讯云没有法语 / 德语 / 俄语 / 西班牙语的实时识别引擎**：选到这些语言时会明确提示"换服务商或改回「自动」"，
  不会拿中文引擎瞎认
- **个人词典对腾讯云不生效**：腾讯热词要在控制台预建词表拿 ID，本程序未接（界面已注明）；千问与豆包填写即生效
- **豆包选语言会切到整句模式**：官方 `language` 参数只在整句端点生效，所以选定语言后出字比「自动」晚一两秒
- **千问选语言不产生任何参数**：千问模型自身多语种自动检测，界面已提示"保持自动即可"

## 12. 升级指南（任意旧版 → 1.4.0）

1. 退出正在运行的旧实例（托盘图标右键 → 退出）
2. 用 `BBVoxi-1.4.0.exe` 覆盖旧 exe（推荐放在同一目录，开机自启的路径就不用改）
3. **本版有一次性配置迁移**（配置版本 **2 → 3**）：老配置里"从没动过"的**千问旧默认模型 3.0**
   会自动升级为 **3.1**（自己填过的模型名原样保留），迁移结果写回文件并记一条日志；
   其余设置（服务商、凭据、快捷键、识别选项、开机自启、主题）**全部原样保留**
4. 新增的「个人词典」`hotwords` 与「识别语言」`language` 两个字段，老配置里没有会自动补默认
   （空词表 / `auto`）—— **行为与升级前完全一致**，不动它就是老样子
5. 界面会变成三页签布局：凭据在「语音服务」、识别开关与语言在「识别选项」、快捷键 / 开机自启 / 主题在「通用」

## 13. 安全与隐私声明

- 音频只在按下快捷键期间采集，并直接推送到你在设置里选择的服务商；本程序**不采集、不上传**
  任何其他数据，无遥测、无统计
- 配置与日志只落在本机 `%APPDATA%\BBVoxi\`；日志不含音频与密钥（密钥只存配置文件）
- 剪贴板只在本机读写，用于"结果留一份"与兜底粘贴，不会把剪贴板内容发送到任何地方
- **个人词典（热词）会随识别请求发送给你选择的服务商**（这是热词生效的前提）—— 请勿在词典里
  填写你不希望上传的内容；这不是新增的数据通道，与你说的每句话一样都只发往你自己配置的服务商
- 本版新增的界面文案与语言选项全部是本地静态内容，不产生额外网络请求
