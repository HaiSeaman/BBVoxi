## 二、逐项根因分析

### ① 测试模式仍会外打（高）

**现象**：点「测试识别（5 秒）」说完话 → 结果不只显示在窗口里，还会被打进设置窗背后的那个程序；同时设置窗会被收起（主人正盯着它看结果）。

**根因**：测试模式此前是用 `LiveTyper::new(cfg.options.live_typing && !test)` 表达的 —— 即把 `enabled` 置为 `false`。但 `enabled` 的语义是「**这次不边说话边打字**」，而收尾的 `finish()` 出于设计**故意不看 `enabled`**（关掉实时输入时，收尾要一次性打出全文，这正是正常行为）。两个概念共用一个布尔量，于是测试模式在收尾阶段被当成"关掉实时输入的普通会话"，把整段文字注了出去。

**验证证据**（修复前用纯逻辑探针复现，不注入任何按键）：

```
测试模式收尾仍会外打：Some(Diff { backspaces: 0, append: "你好" })
```

**修复**：给 `LiveTyper` 增加独立的 `muted` 状态（`LiveTyper::muted()`），`blocked()` = `muted || abandoned || failure`，`sync/finish` 都过这一关；`session.rs` 里测试会话另加一道显式短路（连 `ensure_target_focus` 都不执行，设置窗不会消失）。**两层防护**：即使将来有人删掉 session 里的分支，typer 自身也不会注入。

**注意**：这是 v1.0 起就存在的缺陷，不是上一轮改动引入的。

### ② 收尾前漏查前台窗口（中高）

**现象**：按住快捷键说话，松手后、最终结果到达之前切到别的窗口 → 迟到的补打（甚至退格）落进新窗口，退格会删掉主人正在编辑的内容。

**根因**（这是同一个坑的**第二次**出现）：
- 第一次：收尾完全没校验窗口；
- 上一轮补了校验，但只补在「收到带文字的识别结果」这一处（`session.rs` 主循环与收尾等待循环），而 `finish()` 之前没有再校验 —— **等待最终结果期间切走窗口，是没人发现的**。

根因不是"某个调用点写漏了"，而是**校验被设计成一次额外调用**：只要它和"真正输入"不在同一个地方，就会有人漏掉。

**修复**：把「开始录音时的前台窗口」交给 `LiveTyper` 自己持有，`sync()` 与 `finish()` 都新增**必填参数** `now`（此刻的前台窗口），函数内部先 `guard(now)` 再决定是否输入。调用方不传就编译不过 —— 校验从"靠自觉"变成"编译期强制"。收尾处另有一次显式校验，用于把顺序理顺（确定不输入时不必再去收起设置窗）。

### ③ 最后一包带着文本时不结束会话（中）

**现象**：腾讯云服务商下，松手后界面仍显示"录音中"，要等满 8 秒超时才开始收尾。

**根因**：腾讯把结束标记 `final=1` 和最后一句的文本放在**同一个包**里；而 `parse_json` 是**先判 `slice_type`、后判 `final`**，于是这一包命中"稳态文本"分支，`Parsed::Finished` 永远不会返回，`AsrClient.done` 一直是 `false`。收尾等待循环只能靠「服务端主动关连接」或「8 秒超时」退出。

**顺带发现**：豆包的最后一包（flags `0b0010`）同样可能同时携带新定稿的句子，有**完全相同**的缺陷 —— 上一轮报告只指出了腾讯，实际两家都有。

**修复**：`Parsed::Text` 增加 `finished: bool`；腾讯填 `is_final`、豆包填最后一包标记；累积逻辑从 `AsrClient::handle` 抽成独立的 `Transcript`（这样才能脱离 WebSocket 单测 —— 这个缺陷恰好就在这层）。

> 遗留：服务端是否主动关闭连接，没有真 Key 无法端到端确认。本修复的价值在于**让"它关不关都不影响"**。

### ④ 低于 16kHz 的输入不会被升采样（中）

**现象**：用蓝牙耳机的"免提/通话"模式（常见 8 kHz 单声道）时，识别结果基本是乱码；日志里没有任何提示。

**根因**：`Decimator`（盒式滤波）的实现是"把多个输入样本按 `floor(idx/step)` 分箱取均值"，**原理上只能做降采样**。当输入率低于输出率时 `step < 1`，每个输入样本各占一个分箱，退化成"一进一出"——输出速率仍是 8 kHz，却被贴上 16 kHz 的标签送给服务端，等于慢放一倍。

**验证证据**（纯函数探针）：

```
Decimator::new(8000, 16000) 喂 8000 个样本 → 只输出 7999 个（应为 16000）
```

**修复**：新增 `Interpolator` 线性插值升采样（第 m 个输出样本取输入时间轴 `m × 输入率/输出率` 处的插值），与 `Decimator` 组成 `Resampler` 枚举，按输入率自动选路；日志写明走的是哪条路。
**为什么不能只改旧算法**：分箱取均值无法凭空造出样本，升采样必须在两个样本之间插值；顺带避免了"每个样本重复两遍"（零阶保持会引入频谱镜像）。

### ⑤ 切窗口后两种开关行为不一致（低）

**现象**：中途切走窗口时，开着「边说话边打字」→ 一个字都不打；关着 → **整段文字被打进新窗口**。

**根因**：上一轮新增的 `abandoned` 标记只在 `enabled == true` 时才置位（`disable()` 内部判断），"关着实时输入"这条路径被漏掉了。虽然关着实时输入时 `sent` 为空、不存在退格误删，但把结果打进主人中途切过去的窗口，**同样是打错地方**。

**修复**：新的 `abandon()` 不再看 `enabled`，切走即放弃；删掉语义含混的 `disable()`。

> ⚠️ **行为变更提示**：关着「边说话边打字」时中途切窗口，现在**不再**自动输入（会提示"已放弃"）。这是本轮替用户做的取舍 —— 规则统一为「按快捷键时盯着哪个窗口，字就只往那个窗口写」。

### ⑥ 三处小毛病（低）

| 问题 | 说明 | 处理 |
|---|---|---|
| `nonce()` 取模后截断 | `uuid % 9_999_999_999` 之后再 `as u32`，而 u32 最大只有 4_294_967_295，注释声称的区间根本达不到（值仍是随机的，因此无害） | 改为 `1 + uuid % 999_999_999`，与注释一致 |
| 测试模式计时器错位 | 界面计时从"开始连接"起算，而 5 秒测试上限从"连上之后"起算 → 测试窗显示"录音中 00:07"却只录了 5 秒 | 两者对齐到同一时刻（"请说话…"出现时） |
| README 文档漂移 | 写"单元测试 56 条"（实际 82）、写日志"10 万行上限"（代码是单份 2 MB + 2 份滚动） | 按代码实际修正 |

## 三、审查过、确认无问题的部分

- **音频链路**：48k/44.1k → 16k 的盒式滤波降采样（输出速率精确、电平不失真）、100ms 分帧、采集线程独立于 tokio、缓冲满只丢帧不中断
- **注入**：`KEYEVENTF_UNICODE` 代理对拆分、修饰键重置**必须与文本同批**（否则 Ctrl 消息会插回队列）、错误码 5（UIPI）单独提示、`dwExtraInfo` 标记双保险
- **热键钩子**：`armed`/`held` 双状态判定、长按自动重复全部吞掉、裸按键 keyup 放行（不卡键）、左右修饰键变体齐全、换键时清 `armed`
- **千问协议**：`run-task` → 二进制音频 → `result-generated`（`sentence_end` 区分中间/定稿）→ `finish-task`；心跳包被忽略
- **豆包协议**：四段式二进制头拆帧、gzip 解包、`consumed` 游标不重复统计定稿句、异常关闭带原因
- **腾讯协议**：HMAC-SHA1 签名参数字典序、`secret_id` 在 URL 中、`slice_type` 分段语义
- **配置持久化**：原子写（先写临时文件再改名）、旧配置字段忽略、损坏时回退默认
- **日志**：滚动 + 多实例串行化、本地时间戳、panic 带文件行号

## 四、过程中出现的问题与处理（如实记录）

1. **`cargo fmt` 工具版本漂移**：本机 rustfmt（Rust 1.97）比代码写作时使用的版本新，`cargo fmt` 重排了 5 个与本轮修复无关的文件（`hotkey.rs` / `log.rs` / `main.rs` / `ui.rs` / `config.rs` 中的历史行）。
   **处理**：逐一还原这些"作者原有行"的格式，只保留本轮新写代码的规范格式。
   **结论**：本仓库当前 `cargo fmt --check` **不通过**，全部落在历史代码上（doubao 4 处、hotkey 2 处、ui 2 处、config/log/main 各 1 处），不是本轮引入。要统一格式，自行执行一次 `cargo fmt` 即可。

2. **备份还原后 Cargo 未重建**：变异检查期间备份/还原源码时，文件修改时间被还原成旧值，Cargo 增量构建判定"无需重建"，跑测试用的还是被改坏的旧二进制 —— 一度误判为"还原失败"。
   **处理**：刷新源文件时间戳后重跑，确认 82 条全绿。

3. **自检脚本自身的路径 bug**：用 PowerShell 比对备份与工作区时拼错了目录层级，误报"14 个文件全部备份缺失"（实际一个都没丢）。
   **处理**：改用逐文件 SHA-256 比对，确认恢复无损。

4. **回归测试在"故意改坏"状态下会真的注入一个字符**：测试探针沿用项目既有约定（用单字符 `x`，即使将来有人改坏也只会漏出一个 `x`）。正常绿状态下不注入任何内容。

5. **同一个坑的第二次出现（详见 ②）**：说明"校验放在调用点"这种设计不可靠，本轮据此改成编译期强制。

6. **腾讯缺少端到端实测**：见 ③ 的遗留说明。

## 五、验证方式（为什么这 82 条测试可信）

本轮严格按 TDD 执行：**每条修复先写会失败的测试、确认它失败的原因正确，再写最小实现让它通过**。

在此之上做了一轮 **变异检查**（把修复逐个"改坏"，看测试抓不抓得住）：共制造 7 处变异，**8 条测试失败，与预期一一对应**，改回后再次全绿。对应关系：

| 制造的变异 | 失败的测试 |
|---|---|
| `blocked()` 去掉 `muted` | `muted_session_never_types` |
| `finish()` 去掉窗口校验 | `finish_rechecks_the_target_window` |
| `abandon()` 加回 `enabled` 判断 | `switching_windows_abandons_even_when_live_typing_was_off` |
| `Transcript::absorb` 忽略 `finished` | `transcript_marks_done_when_a_text_packet_also_finishes` |
| 腾讯 `finished: false` | `final_packet_with_text_also_ends_the_session` |
| 豆包 `finished: false` | `last_packet_with_text_also_finishes` |
| `Resampler` 强制走降采样 | `upsamples_low_rate_input_to_target_rate`、`upsampling_interpolates_between_neighbours` |

这证明这些测试**不是摆设**——把修复拿掉，它们一定红。

**本轮未做的验证**：实机图形界面/端到端自动化测试（项目约定只做代码与逻辑验证）。因此下列四项需要人工冒烟：① 测试识别时窗口是否保留且不外打；② 录音中途切窗口是否正确放弃；③ 腾讯云松手后是否立即收尾；④ 蓝牙耳机（8 kHz）下日志是否出现"线性插值升采样"。
