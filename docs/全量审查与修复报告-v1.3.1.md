## 2. 【严重】会丢字 / 卡死 / 界面卡住

### 2.1 录音尾巴固定丢最多 100 毫秒语音（含一处竞态）

- **现象**：每次松开快捷键，最后一点语音没被识别到。
- **根因**：停止条件置位后，采集回调直接返回；重采样器里压着的样本与不足一帧的残料随 `drop(stream)` 一起消失。
- **修法**：
  1. `Feed::push` 在 `stopped` 时把 `Resampler::flush()` 与残帧**补发**进通道（**不补零**：ASR 接受任意长度 PCM，真实短帧比假静音更准）；
  2. `Resampler::flush` / `Decimator::finish` 新增，用于取出内部压着的样本；
  3. 会话侧 `capture.stop()` 后**等待 60 毫秒**再收干 —— 采集线程每 50ms 轮询停止标志，不留间隔的话收干会抢在补发之前读到"通道已空"，等于白补。
- **位置**：[audio.rs:186](file:///d:/AI/Github/BBVoxi/BBVoxi/src/audio.rs#L186-L204)、[session.rs:328](file:///d:/AI/Github/BBVoxi/BBVoxi/src/session.rs#L328-L334)
- **验证**：不碰设备的纯函数用例（`upsamples_low_rate_input_to_target_rate` 等）；补发路径依赖真实设备，未做自动化（项目约定不做 GUI/硬件测试）。

### 2.2 麦克风出错后界面永远停在"录音中"

- **现象**：拔掉麦克风 / 设备被独占，界面一直显示录音中，会话永不结束。
- **根因**：`on_err` 回调只写日志，既不记录原因也不终止采集，`rx` 一直不关闭。
- **修法**：`on_err` 存下错误文本并置位 `stopped`（采集线程随之退出、`rx` 关闭）；会话在收到 `None` 时读取 `Capture::error()`，如实报「麦克风异常：xxx」。
- **位置**：[audio.rs:104](file:///d:/AI/Github/BBVoxi/BBVoxi/src/audio.rs#L104-L113)、[session.rs:336](file:///d:/AI/Github/BBVoxi/BBVoxi/src/session.rs#L336-L342)

### 2.3 网络半死 → 会话永久挂起 → 之后所有热键失灵

- **现象**：Wi-Fi 掉线（无 RST）时，松开快捷键没反应，程序像死了。
- **根因**：TCP 写缓冲填满后 `sink.send(...).await` **永不返回**，会话主循环卡死，`Cmd::Stop` 再也收不到。
- **修法**：新增 `SEND_TIMEOUT = 5s` 与 `send_timed()`，覆盖启动帧、音频帧、结束帧；收尾阶段每一步（收干发送、等待最终结果）同样限时。
- **位置**：[asr/mod.rs:29](file:///d:/AI/Github/BBVoxi/BBVoxi/src/asr/mod.rs#L29-L33)、[asr/mod.rs:359](file:///d:/AI/Github/BBVoxi/BBVoxi/src/asr/mod.rs#L359-L365)、[session.rs:263](file:///d:/AI/Github/BBVoxi/BBVoxi/src/session.rs#L263-L273)

### 2.4 收尾"边录边发"永远结束不了

- **根因**：原实现先 drain 再 `drop(capture)` —— 采集线程仍在以每 100ms 一帧供货，drain 永远有新帧。
- **修法**：改为「`capture.stop()`（让采集线程收工并补发尾帧）→ 收干（上限 20 帧，每步 5 秒超时）→ `drop`」。
- **位置**：[session.rs:305](file:///d:/AI/Github/BBVoxi/BBVoxi/src/session.rs#L305-L352)
- **备注**：子代理原计划的字面写法"先 `drop` 再 drain"不可实现（`drop` 会连 `rx` 一起丢），改为语义等价的"先停再收干"。

### 2.5 注入失败过之后结果被静默丢弃

- **根因**：`finish()` 只要没到注入那一步就返回 `Ok(())`，调用方以为"已交付"，结果两条路都没走。
- **修法**：`finish` 改为 `Result<bool>` 三态 —— `Ok(true)` 已交付/无需输入、`Ok(false)` 放弃输入（切窗口）、`Err` 失败；调用方对后两种一律 `hand_off_to_clipboard` + `shared.report/fail`。
- **位置**：[typer.rs:223](file:///d:/AI/Github/BBVoxi/BBVoxi/src/typer.rs#L223-L251)、[session.rs:434](file:///d:/AI/Github/BBVoxi/BBVoxi/src/session.rs#L434-L458)

### 2.6 "让主人看提示"却弹不出窗口（本报告作者定位）

- **根因**：会话线程发出 `Visible(true)` 后，`App::logic` 在 `shown == false`（静默启动/收起到托盘）时**每帧**补发 `Visible(false)`，把请求当场盖掉 —— 主人什么也看不到。
- **修法**：改为**请求位机制**：`Shared::show_settings()` 只置位 + `request_repaint()`；UI 线程在 `logic()` 里 `take_show_request()` 后走正规的 `App::show_settings()`（更新 `shown`、搬回屏幕内、延后一帧抢焦点），且处理**排在下发 `Visible(false)` 之前**。
- **位置**：[session.rs:88](file:///d:/AI/Github/BBVoxi/BBVoxi/src/session.rs#L88-L96)、[main.rs:412](file:///d:/AI/Github/BBVoxi/BBVoxi/src/main.rs#L412-L417)
- **验证**：`show_request_is_taken_exactly_once`（新单测，覆盖"取走即清零"语义）。

### 2.7 逐字注入部分成功 → 整段重粘 → 重复打字

- **根因**：`SendInput` 只提交了一部分事件时，兜底把**整段**（含已打进去的部分）交给剪贴板粘贴。
- **修法**：`type_text` 返回**实际提交的 UTF-16 编码单元数**，`execute` 仅当"提交数 ≥ 期望数"才记账；不足时用新纯函数 `tail_after_units()` 取出**未提交的尾巴**，只粘这段。
- **位置**：[injector.rs:97](file:///d:/AI/Github/BBVoxi/BBVoxi/src/injector.rs#L95-L111)、[typer.rs:69](file:///d:/AI/Github/BBVoxi/BBVoxi/src/typer.rs#L69-L82)、[typer.rs:259](file:///d:/AI/Github/BBVoxi/BBVoxi/src/typer.rs#L259-L298)
- **验证**：`tail_after_units_returns_only_the_uncommitted_suffix`、`typeable_units_counts_units_without_cr`。

## 3. 【中等】数据与状态不一致

### 3.1 豆包二遍识别丢句 / 重复（下标游标必错）

- **根因**：只增不减的 `consumed` 游标依赖 `utterances` 数组下标稳定；二遍识别会改写、重排、缩短数组 → 数组一缩 `while consumed < list.len()` 永不成立（后半段全丢），改写版落到"新下标"又被当新句追加（多打一份字）。
- **修法**：弃用下标，改为「**当前全部定稿片段拼接快照**」与上次上报值比较；上报时使用**固定片段编号 `DOUBAO_FINAL_ID = 0`**，触发上层 `Transcript` 的"同号替换"语义实现整段覆盖。
- **位置**：[doubao.rs:180](file:///d:/AI/Github/BBVoxi/BBVoxi/src/asr/doubao.rs#L180-L240)、[doubao.rs:36](file:///d:/AI/Github/BBVoxi/BBVoxi/src/asr/doubao.rs#L30-L36)、[asr/mod.rs:230](file:///d:/AI/Github/BBVoxi/BBVoxi/src/asr/mod.rs#L230-L265)
- **正确性核对**：`show_utterances: true` 保证走数组路径；重复快照被 `definite != self.reported` 挡掉；改写快照走同号替换（`truncate(last_final_bytes)` + 追加）；数组缩短同样触发整段替换。已逐场景推演。

### 3.2 腾讯云中间结果被丢弃

- **根因**：`slice_type = 0`（语音中间结果）落进了"忽略"分支。
- **修法**：新增 `0 if !text.is_empty()` 分支 —— 非终包按 `Partial`、终包按 `Final{finished:true}`。
- **位置**：[tencent.rs:90](file:///d:/AI/Github/BBVoxi/BBVoxi/src/asr/tencent.rs#L88-L100)
- **验证**：新增两条单测并更新原 `missing_slice_type...` 的期望。

### 3.3 命名键（退格/回车/Tab）不带扫描码

- **根因**：只读扫描码的程序（游戏、部分远程桌面）看不见 `wScan = 0` 的按键 —— 字打出去了、退格删不掉、回车不换行。
- **修法**：新增 `push_key_stroke()`，统一用 `MapVirtualKeyW(vk, MAPVK_VK_TO_VSC)` 取真实扫描码（与 `paste_events` 口径一致）。
- **位置**：[injector.rs:161](file:///d:/AI/Github/BBVoxi/BBVoxi/src/injector.rs#L155-L165)
- **验证**：`named_keys_carry_real_scan_codes`、`newline_maps_to_enter_keycode`。

### 3.4 服务端帧无上限堆内存

- **根因**：通道无界，服务端推送快于消费时内存无上限增长。
- **修法**：`MSG_CHANNEL_CAPACITY = 64` 有界通道 + `try_send`（满了丢帧不阻塞，读取任务永远向前走）+ 限流日志（首条与每 64 条）；`TrySendError::Closed` 时跳出读取循环。
- **位置**：[asr/mod.rs:33](file:///d:/AI/Github/BBVoxi/BBVoxi/src/asr/mod.rs#L30-L33)、[asr/mod.rs:438](file:///d:/AI/Github/BBVoxi/BBVoxi/src/asr/mod.rs#L436-L455)

### 3.5 剪贴板清空失败泄漏全局内存

- **根因**：`EmptyClipboard()?` 提前返回，路径上没有 `GlobalFree`（`GMEM_MOVEABLE` 是系统全局内存）。
- **修法**：手动处理返回值，失败时 `GlobalFree` 后再返回错误。
- **位置**：[clipboard.rs:85](file:///d:/AI/Github/BBVoxi/BBVoxi/src/clipboard.rs#L85-L91)

### 3.6 豆包坏帧被静默吞掉

- **修法**：解帧失败记日志（帧长 + 前 16 字节 hex，不打印整帧），连续 5 次返回 `Parsed::Error` 结束会话。
- **位置**：[doubao.rs:136](file:///d:/AI/Github/BBVoxi/BBVoxi/src/asr/doubao.rs#L136-L159)

### 3.7 手动双击 exe 被误判成开机自启

- **根因**：老格式启动项（无参数）与手动双击无法区分。
- **修法**：抽出纯函数 `boot_decision(has_flag, legacy_entry, uptime_ms)`：有 `--autostart` → 自启；老格式 + 系统开机 < 5 分钟 → 自启并升级注册表项；其余 → 手动双击（弹窗）。
- **位置**：[autostart.rs:72](file:///d:/AI/Github/BBVoxi/BBVoxi/src/autostart.rs#L63-L89)
- **验证**：`boot_decision_matrix`（枚举各组合）。

### 3.8 窗口最小化后从托盘打不开 / 抢前台失败 / 托盘永久放弃

- **最小化**：显示窗口的正确顺序是「先 `Minimized(false)` → 再 `Visible(true)` → 延后一帧 `Focus`」；
- **抢前台**：`pending_focus_at` 记录 `cumulative_pass_nr()`，只有帧号前进后才发 `Focus`（同帧下发在 Windows 上经常失败）；
- **托盘**：创建失败改为 30 秒退避重试（`tray_failed_at`），不再永久放弃；
- **互斥量**：单实例互斥量创建失败改为"继续启动 + 日志留痕"。
- **位置**：[main.rs:340](file:///d:/AI/Github/BBVoxi/BBVoxi/src/main.rs#L340-L357)、[main.rs:427](file:///d:/AI/Github/BBVoxi/BBVoxi/src/main.rs#L427-L441)、[main.rs:459](file:///d:/AI/Github/BBVoxi/BBVoxi/src/main.rs#L459-L472)、[main.rs:192](file:///d:/AI/Github/BBVoxi/BBVoxi/src/main.rs#L192)

### 3.9 日志可能重入自锁 / 滚动失败静默 / 边界差一

- **修法**：`IN_LOG` 重入保护（已在写日志则直接返回，**绝不自死锁**；代价是"别的线程正在写日志时本条会被丢弃"，已在注释说明）；滚动判定 `>=`；`rotate` 返回 `io::Result`，失败 60 秒退避（`LAST_ROTATE_FAIL`）并留痕；`eprintln!` 改为 `writeln!(stderr)` 避免死锁路径。

## 6. 修复过程中的偏差与处理（如实记录）

1. **"先 `drop(capture)` 再 drain"无法字面实现**：`drop` 会连 `rx` 一起释放，drain 将无数据可读。改为语义等价的「先 `stop()` → 等待 60ms → 收干 → `drop`」。
2. **子代理上报的遗留缺陷**：`Shared::show_settings()` 只发 `Visible(true)`，会被 `App::logic` 的隐藏补发盖掉 —— 由主干复核后改为请求位机制（§2.6）。
3. **豆包幂等实现与初版方案不同**：初版计划"逐片段特征集合"，实际落地为"整段快照 + 固定编号"。已按 §3.1 逐场景推演核对，结论为**满足**"重复不重复、改写整段替换、数组缩/重排不丢结果"三项要求。
4. **`is_away()` 死代码**：`finish` 三态化后失去调用点，clippy 报警告，已删除并改测试读字段。
5. **收尾竞态**：修复尾帧补发时发现"补发与收干抢跑"的次级竞态，追加 60ms 等待（§2.1）。

## 7. 刻意不修（Windows 平台限制，附原因）

| 项 | 为什么修不了 |
|---|---|
| 目标程序"假装收下了"注入的字（`SendInput` 返回入队数 ≠ 目标接受） | Windows **没有**通用 API 能查询"目标是否真正处理了事件"。已覆盖可检测的部分（提交数不足触发兜底），并用「识别结果总留一份到剪贴板」兜住数据安全 |
| 同一窗口内主人自行移动光标后，纠错退格可能删到非预期位置 | 光标位置只存在于目标进程内部，跨进程无法可靠读取；无信号可判 |
| 含 `Win` + 普通主键的组合被系统抢先响应 | Windows 保留键的既定行为（开始菜单在 `Win` 松开时弹出），非本程序可控 |
| 剪贴板被占用时的阻塞等待（上限 80ms） | 仅出现在失败兜底路径；换来的是"绝不把全系统剪贴板锁死" |
| `read_text` 无法区分"剪贴板里不是文本"与"被占用读不到" | 两者都只能返回 `None`；调用方的处理一致（都不还原、不覆盖），已文档化 |
