## 一、一分钟认识 BBVoxi

**BBVoxi 是一个常驻 Windows 系统托盘的语音输入法**：按住快捷键说话 → 松开 → 识别出的文字**直接出现在光标所在位置**，就像用键盘打字一样自然。

它解决的问题很具体：**"我想说话出字，但不要多一个窗口、不要打断我正在复制的东西、不要等我松手才看到字。"**

| 你熟悉的方案 | 常见体验 | BBVoxi 的做法 |
|---|---|---|
| 系统自带语音输入 | 需要联网、入口深、对中文支持一般 | 走你自己的 ASR 账号，随便换服务商 |
| 翻译/听写软件 | 弹一个悬浮窗显示结果，你要自己复制粘贴 | **没有悬浮窗**，文字直接进光标处 |
| 剪贴板类工具 | 识别结果先进剪贴板，覆盖你正在复制的内容 | **完全不碰剪贴板** |
| 各类语音转文字 App | 先录完整段、等一会儿、再一次性出字 | **边说边出字**，识别纠正时自动回退重打 |

**一句话：它是"键盘的替代品"，不是"另一个聊天框"。**

## 二、1.0.0 的定位与设计取舍

1.0.0 是**第一版正式版**，所以取舍很明确：**只做一件事，并把它做扎实**。

| 决定 | 理由 | 代价 |
|---|---|---|
| **只做中文识别** | 目标场景就是中文输入法 | 英文/多语言用户暂时用不了 |
| **不做本地识别模型** | 本地模型体积大、要 GPU、装完几个 GB；走云服务才能保持"单文件 8 MB 免安装" | 必须联网，且要自己准备 ASR 账号 |
| **删除悬浮条** | 悬浮条会抢焦点，导致"字打到自己窗口上"；而且它是多余的窗口 | 状态反馈改为托盘图标（红点/橙点）+ 托盘提示文字 |
| **删除录音时长上限** | 用户反馈希望"按多久说多久" | 腾讯引擎自身限制 60 秒（服务端限制，客户端改不了） |
| **不做自动静音断句** | 会误判"思考中的停顿"为说完 | 托盘"开始录音"需要再点一次"停止录音" |
| **不做安装包** | 单文件 exe 免安装、免运行库、绿色可删 | 没有开始菜单项、没有桌面快捷方式 |

## 三、开发历程：七轮迭代与七个真实 Bug

1.0.0 不是一次写成的，而是**七轮"发现问题 → 定位根因 → 修复 → 补回归测试"**的结果。这一节是本文最有价值的部分，因为每一个 Bug 都留下了可复现的教训。

### 第 1 轮：从 0 到能跑（M1）
打通音频采集 → 三家 ASR → 松手出字的主链路。此时还是"松手后一次性出字"，并且有一个**悬浮条**显示识别结果。

### 第 2 轮：闪退修复 + 图标替换（第 1 个严重 Bug）

**现象**：点「测试麦克风与连接」，软件**直接消失**，没有任何报错提示。

**定位过程（先证据后结论，而不是猜）**：
1. 读日志 → 最后一行是「麦克风已启动」，之后再无任何记录；
2. 代码里连接失败会写日志，既然没写 → 进程没走到那一步就死了；
3. 查 `Cargo.toml` → release 配置里有 `panic = "abort"`，**任何 panic 都会静默退出**，所以看不到任何提示；
4. 写回归测试复现（用无效 Key 走真实 TLS 路径）→ panic 原文：
   ```
   panicked at rustls-0.23.44/src/crypto/mod.rs:249:
   Could not automatically determine the process-level CryptoProvider from Rustls crate features.
   ```

**根因**：`tokio-tungstenite` 的 `rustls-tls-webpki-roots` 特性**只给 TLS 传输层，没给加密后端**（ring / aws-lc-rs 都没启用）。rustls 0.23 在第一次建 TLS 连接时自动选后端，选不出来就 panic。而这个"测试"按钮是程序里**第一次真正发起 WSS 连接**的地方，所以现象是"一点就闪退"，且**三家服务商全中**。

**修复 + 三层防护**（不只修表面）：
- 显式启用加密后端 `ring`，并在连接前幂等安装进程级 provider；
- ① 日志层：`panic hook` 把**文件名 + 行号 + 消息**写进日志；
- ② 编译层：release 去掉 `panic = "abort"`，改回 `unwind`；
- ③ 运行层：会话逻辑用 `catch_unwind` 包裹，单次识别异常只结束本次会话，程序继续活着并提示用户。

> **教训**：常驻程序里 `panic = "abort"` 是最糟的失败方式——进程静默消失、零线索。**任何"没日志的崩溃"都该先去查 panic 策略。**

### 第 3 轮：快捷键完全失效（第 2 个严重 Bug）

**现象**：设置好快捷键，按了**毫无反应**，日志里从来没有「快捷键按下 → 开始录音」。

**根因**：Windows 低级键盘钩子（`WH_KEYBOARD_LL`）上报的修饰键是**左右分开**的虚拟键码——左 Ctrl 是 `VK_LCONTROL(0xA2)`，钩子**不会**上报通用的 `VK_CONTROL(0x11)`。而判定表里写了右 Ctrl（0xA3）却**偏偏漏了 0xA2**，也就是**最常用的左 Ctrl 从来没被记进状态**，于是 `mods_ok` 永远为 false，`Ctrl + 任意键`全部按不动。

**为什么能藏这么久**：钩子回调整段在 `unsafe extern "system"` 里，**没法单元测试**。这一轮把判定逻辑抽成纯函数：

```rust
pub fn decide(hk: Hotkey, mods: Mods, vk: u32, down: bool, armed: bool) -> Decision
```

抽出来之后新写的测试**第一次运行就红了**，直接指到问题所在。

**修复**：
- 修饰键判定收敛为**单一事实来源** `hotkey::MODIFIERS`（Ctrl/Alt/Shift 各 3 个变体 + Win 2 个，共 11 项），键盘状态跟踪与判定共用同一张表，杜绝"两处各写一份"再次漏项；
- 新增 6 条测试覆盖真实按键序列（含"先松 Ctrl 再松 1 也要停止录音"）。

**顺带修掉的两个隐患**：
| 隐患 | 后果 | 修复 |
|---|---|---|
| 保存配置时不调用 `set_current()` | 改完快捷键**必须重启才生效**，用户以为坏了 | 保存即生效；格式非法则拒绝保存并红字提示 |
| 捕捉模式下按到不支持的键，钩子被**永久暂停** | 之后所有快捷键都失灵 | 窗口失焦/取消/关闭都会退出捕捉状态 |

### 第 4 轮：松手不出字 + 界面重做（第 3 个严重 Bug）

**现象**：按住说话→松开，**不出字**；要等 55 秒上限到了才收尾输出。

**根因**（三行代码的经典事故）：
```rust
// 修复前
cmd = rx.recv() => match cmd {
    Some(Cmd::Start) | None => break,
    Some(_) => {}          // ← Cmd::Stop 落进这里，什么也没做
},
```
钩子确实在松手时发了 `Cmd::Stop`，但会话主循环把这个分支当成"无关指令"忽略掉了——**松手的信号被自己吞了**。

**顺带发现的第二个 Bug**：连接建立较慢时音频缓冲会满，原来"缓冲满"被误判成"接收端已退出"，于是**直接停掉麦克风线程，整场录音作废**。修复后区分两种情况：缓冲满只丢帧 + 记一次日志，只有接收端真关闭才收工；缓冲也从 32 帧（3.2 秒）提到 100 帧（10 秒）。

**同轮 UI 改版**：设计基调直接取自应用图标（靛蓝 `#5457E5` → 青绿），**全程只用一个强调色**，其余中性灰阶，靠留白与卡片层次撑现代感；品牌栏 + 卡片分区（语音服务 / 快捷键 / 识别选项 / 最近识别）+ 底部固定操作条（保存按钮永远可见）；跟随系统深浅色切换，并对两套配色写了**对比度断言测试**。

### 第 5 轮：边说话边打字（核心特性落地）

**关键判断**：三家服务商**本来就都是流式的**（千问 `sentence_end=false`、豆包 `definite=false`、腾讯 `slice_type=1` 都是中间结果），所以问题不在服务端，而是**软件之前只在松手后才打字**。

**为什么不能"来一段打一段"**：中间结果会被不断修正（同音字、标点、断句）。若直接追加，屏幕会留下错误前缀——先说成"今天天汽"再改成"今天天气"，追加就变成"今天天汽今天天气"。

**采用的算法**（Windows 语音输入、安卓输入法都是这个思路）：
```
sent    = 已经打进目标程序的文本
desired = 当前期望文本（已定稿 + 当前句中间结果）
common  = longest_common_prefix(sent, desired)
→ 先退格 (len(sent) - len(common)) 次，再补打 desired 里多出来的部分
```

| 情况 | 实际动作 |
|---|---|
| 文字变长（正常说话） | 只补打 1~2 个字 |
| 识别纠正某个字（天汽→天气） | 只退格 1 次、重打 1 个字 |
| 定稿补了句号 | 只补打 1 个字符 |
| 整句被重写 | 退格整句重打（少见） |

**配套的三条安全设计**：
- **录音中途切走窗口 → 立即停用实时输入**（否则退格会砸进别人的输入框），改到收尾时按当时焦点一次性输入；
- **测试模式永不外打**（结果只显示在窗口里）；
- **可关闭**（设置里取消勾选就回到"松手后一次性出字"）。

### 第 6 轮：实时输入卡顿（第 4 个严重 Bug，有日志实证）

**现象**：打字**一卡一卡**，有时卡很久才出字。日志里有一段铁证：

```
[1789038548] 快捷键按下 → 开始录音
[1789038550] 等待修饰键松开超时，仍按当前状态输入   ← 每次打字前卡 1.5 秒
...（同一场录音里出现 6 次）
[1789038558] 快捷键松开 → 结束录音
```

**10 秒的录音里，9 秒是纯等待**。

**根因**：上一轮为防止 `Ctrl+A` 误触发，在每次注入前加了"等修饰键松开（最多 1.5 秒）"。但**按住说话时用户正一直按着 Ctrl**——这个等待永远等不到。更糟的是它发生在会话主循环里，**把音频发送也一起堵住了**，导致服务端收到的音频出现空档，出字更加又慢又碎。

**修复（业界成熟做法：注入前"清掉"修饰键）**：
1. 注入前补发修饰键的 **KEYUP**，让前台程序认为修饰键已松开；
2. **左右键都发**（只发 `VK_CONTROL` 无效）；
3. 右键是扩展键，要带 `KEYEVENTF_EXTENDEDKEY`；
4. **必须与文本在同一次 `SendInput` 调用内**，否则修饰键消息会重新插回队列。

**为什么不清修饰键会出大问题**：不只是 `Ctrl+A`。我们的自动纠错要发**退格**，而退格是 VK 键——**`Ctrl+退格` 在很多程序里是"删掉整个词"**。所以不清修饰键时，识别一修正就可能一次删掉一整段文字。这个隐患一并修掉了。

删除 1.5 秒等待后，注入变成纯 `SendInput`（亚毫秒级）。

### 第 7 轮：全量审查 + 精简（第 5、6 个 Bug）

**① 长按快捷键时前台出现满屏 `111111`**

**根因**：第 6 轮加的"修饰键 KEYUP"是**我们自己注入的事件**，而钩子在**更新修饰键状态时没有过滤注入事件**——它把自己发的 Ctrl-up 当成了"用户松开了 Ctrl"，于是判定失败、触发键不再被吞，用户长按 `1` 的自动重复**全部漏给了前台程序**。

**修复**：注入事件进入钩子时直接放行、完全不参与任何判断，并给注入的每个事件打上 `dwExtraInfo` 标记做双保险。
```rust
if ignore_event(injected || ours, paused) {
    return CallNextHookEx(...);   // 自己发的事件不参与任何判断
}
```
回归测试模拟 20 次自动重复，断言**全部被吞掉**。

**② 收尾时可能把已经打出来的字删掉（数据丢失）**

`take_result()` 原逻辑是"有定稿就只用定稿"。若最后一句没等到定稿（超时/连接中断），返回文本会**短于**已经写进目标程序的文本，收尾对账时就会**退格删掉用户已经看到的字**。修复：改为「定稿 + 未定稿尾段」合并，并抽成纯函数 `merge_result()` 加测试。

**③ 实时输入失败时界面状态错误**：原来调 `shared.fail()` 会把 `recording` 置为 false——**录音还在继续，界面却显示"没在录音"**。新增 `Shared::report()`：只报错、不动录音状态。

**④ 精简掉的东西**（审查发现）：
| 类型 | 问题 | 处理 |
|---|---|---|
| 重复设计 | 修饰键**两份清单**（这就是漏掉左 Ctrl 的根源） | 合并为单一事实来源 |
| 死代码 | `show_overlay`、`max_record_secs` 随功能删除已移除 | 已删（旧配置残留字段会被忽略，有测试覆盖） |
| 误导文档 | 描述**已删除的悬浮条/时长上限**的旧报告 | 已删除 |
| 无用依赖 | 逐个核对 9 个外部依赖 | **全部在用**，无死依赖 |
| 死代码标记 | `#[allow(dead_code)]` / `todo!` / `unimplemented!` | 全项目 **0 处** |

## 五、技术要点详解

### 5.1 音频链路：为什么必须自己重采样

三家服务商统一要求 **16 kHz / 16 bit / 单声道 PCM**，而麦克风多为 48 kHz 立体声。做法：

- **盒式滤波（分箱取均值）** 而非按样本抽样——44.1 kHz → 16 kHz 这种**非整数比**也能得到精确的输出速率，且避免频谱镜像；
- 采集跑在**独立线程**（cpal 的 `Stream` 不是 `Send`，不能跨线程搬），帧通过**有界 channel**（100 帧 ≈ 10 秒）交给 tokio 会话任务；
- **缓冲满只丢帧、绝不停麦克风**（第 4 轮修的真实 Bug）；
- 100 ms 一帧（三家官方文档都建议 100~200 ms）。

### 5.2 文字注入：不碰剪贴板

- 用 `SendInput` + `KEYEVENTF_UNICODE` **逐字符模拟打字**，完全不用剪贴板——所以不会破坏你正在复制的内容；
- 中文/生僻字走 **UTF-16 代理对**，按字符拆成两次事件（emoji 也能打）；
- **注入前必须"清掉"修饰键**（原因与实现见第 6 轮）；
- 注入失败区分 `ERROR_ACCESS_DENIED(5)`（目标窗口以管理员运行，Windows UIPI 限制），给用户一句人话提示，而不是抛异常码。

### 5.3 三家协议的差异怎么抹平

| | 千问（阿里云百炼） | 豆包（火山引擎） | 腾讯云 |
|---|---|---|---|
| 端点 | `wss://dashscope.aliyuncs.com/api-ws/v1/inference` | `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async` | `wss://asr.cloud.tencent.com/asr/v2/<AppId>?签名` |
| 鉴权 | `Authorization: Bearer <key>` | `X-Api-Key` / `X-Api-Resource-Id` / `X-Api-Connect-Id` | URL 参数签名（HMAC-SHA1 + Base64，字典序） |
| 音频格式 | 裸二进制帧 | **4 字节头 + 4 字节长度 + payload**，JSON 体 gzip 压缩 | 裸二进制帧 |
| 中间结果 | `sentence_end = false` | `definite = false` | `slice_type = 1` |
| 定稿 | `sentence_end = true` | `definite = true`（二遍优化后可能改写中间结果） | `slice_type = 2` |
| 结束 | 文本 `finish-task` | 最后一帧打 `LAST_PACKET` 标记位 | 文本 `{"type":"end"}` |
| 特性 | 需要 `heartbeat: true` 防静音断连 | `consumed` 游标避免重复统计定稿句 | 引擎 60 秒上限 |

统一抽象为 `Backend` 枚举（`start_messages` / `audio_messages` / `finish_messages` / `parse`），上层会话代码**完全不知道**用的是哪家。

### 5.4 容错与可观测性

- 任何 panic 都会带**文件 + 行号**写进日志（第 2 轮加的）；
- 会话过程 `catch_unwind` 包裹：识别出错只结束本次会话，常驻程序继续活着；
- **慢操作监控**：只有单次实时注入 ≥ 80 ms 才写一条 `实时输入偏慢：123ms（退格 2 字，补打 4 字）`，让"卡不卡"有客观数据，不靠感觉；
- 关键节点全有日志：`快捷键按下 → 开始录音`、`ASR 已连接：千问`、`识别完成（N 字）`、`实时输入已关闭：录音过程中切换了窗口`；
- 滚动日志 2 MB × 2 份，多实例写日志串行化。

## 七、如何使用

### 安装（4 步）

1. 下载 `BBVoxi-1.0.0.exe`，放到任意目录（推荐 `%LOCALAPPDATA%\BBVoxi\`），双击运行；
2. 托盘出现图标，首次运行自动弹出设置窗；
3. 选服务商 → 填**你自己的** API Key（腾讯云填 App ID / Secret ID / Secret Key 三元组）；
4. 点「测试识别（5 秒）」说一句话确认能出字 → 点「保存」。

### 三种使用方式

| 方式 | 行为 | 文字去向 |
|---|---|---|
| **按住快捷键**（默认 `Ctrl + 1`） | 按住期间录音，松开即结束并输入 | 直接进光标处 |
| **托盘 → 开始录音 / 停止录音** | 点一次开始，再点一次结束 | 直接进光标处 |
| **设置窗 → 测试识别（5 秒）** | 固定 5 秒自动结束，验证凭据与麦克风 | **只显示在窗口里**，不外打 |

快捷键可在设置里改成任意 `Ctrl / Alt / Shift` + 字母 / 数字 / `F1`~`F12` / 空格，**改完点保存立即生效**；按下时该组合键会被拦截，不会触发浏览器切标签之类的系统快捷键。

### 卸载

直接删除 exe。用户数据保留在 `%APPDATA%\BBVoxi\`（配置 + 日志），想彻底清理就删掉该目录。可选的开机自启是**注册表 `Run` 项**（写你当前用户，不需要管理员权限），在设置里可随时关闭。

## 八、隐私与安全

- **不收集**：用户名、机器码、地理位置、输入法历史、使用统计；
- **不上传**：除你录制的语音之外的任何东西；
- **只发语音**：且只发给你在设置里选定的那家 ASR 服务商，松手即停；
- **API Key 存在本地**：`%APPDATA%\BBVoxi\config.json`，**当前版本是明文**（已知取舍，见路线图）；
- **无遥测、无第三方统计 SDK**。

> ⚠️ 提醒：如果你的用户目录参与网盘/OneDrive 同步，配置文件可能被同步到云端。介意的话请先把该目录排除同步。

## 九、已知限制（1.0.0）

| 限制 | 说明 | 计划 |
|---|---|---|
| **仅 64 位 Windows** | 只发布 `x86_64-pc-windows-msvc`，Win7 / 32 位不覆盖 | 视需求评估 |
| **仅中文识别** | 语言写死中文，界面不暴露语言选项 | 视需求评估 |
| **管理员窗口无法输入** | 目标窗口以管理员权限运行时 `SendInput` 投递不到（Windows UIPI 机制限制），程序会给出明确提示 | 1.x 考虑加"以管理员身份重启"引导 |
| **腾讯引擎 60 秒上限** | 服务端限制，超出会由服务端结束（千问与豆包无此时限） | 客户端已按 55 秒提示 |
| **需要自备 ASR 账号** | 不内置任何公共 Key，也不代付费用 | 设计如此 |
| **实时输入依赖"文本记账"** | 若目标程序对输入做自动改写（如编辑器自动补全、输入法联想），差分可能与实际不同步 | 可在设置里关掉实时输入规避 |
| **托盘"开始录音"需手动停止** | 没有静音自动断句 | 可加 VAD 自动结束（视需求） |
| **无多麦克风选择界面** | 自动使用系统默认输入设备 | 后续 |
| **占内存约 114 MB（常驻）/ 170 MB（窗口可见）** | 主要是 egui + 中文字体的基线开销 | 若要显著降低需换原生 Win32 UI |
| **首次运行需允许麦克风** | 要在 Windows 隐私设置里允许桌面应用访问麦克风 | 系统行为 |
