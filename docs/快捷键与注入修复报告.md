## 一、快捷键完全失效（根因 + 证据）

### 根因

Windows 低级键盘钩子上报的修饰键是**左右分开**的虚拟键码：

| 物理按键 | 钩子上报的 vkCode |
|---|---|
| 左 Ctrl | `VK_LCONTROL` = **0xA2** |
| 右 Ctrl | `VK_RCONTROL` = 0xA3 |
| 左 Alt | `VK_LMENU` = 0xA4 |
| 左 Shift | `VK_LSHIFT` = 0xA0 |

钩子**不会**上报通用的 `VK_CONTROL`(0x11)。而我原来的判定表里写了 `VK_RCONTROL`，**偏偏漏了 0xA2** —— 也就是**最常用的左 Ctrl 从来没被记进状态**，于是 `mods_ok` 永远是 false：

```
Ctrl(0xA2) 按下 → 不在表里 → ctrl 状态仍为 false
    ↓
按下 1 → 要求 ctrl==true → 判定失败 → 不触发、不吞键
```

所以 **Ctrl+1、Ctrl+`（你设置的）、以及所有 Ctrl+X 组合全都按不动**，而这也是为什么日志里从来没有「快捷键按下 → 开始录音」，只有测试按钮和托盘触发的会话。

### 怎么找到的

钩子回调整段都在 `unsafe extern "system"` 里，没法单测 —— 这正是它能藏这么久的原因。这次我把判定逻辑抽成纯函数 `decide(hk, mods, vk, down, armed) -> Decision`，并写测试覆盖真实按键序列。**新写的测试第一次运行就红了**，直接指到 `is_modifier`。

### 修复内容

1. 修饰键判定收敛为**单一事实来源** `classify_modifier()`，左右变体全部列出（Ctrl/Alt/Shift 各 3 个 + Win 2 个），键盘状态跟踪与判定共用同一张表，杜绝再漏项。
2. 新增测试：
   - `all_modifier_variants_are_classified`：11 个修饰键码逐个断言必须被识别
   - `physical_left_ctrl_triggers_the_hotkey`、`press_and_release_triggers_start_then_stop`、`user_backtick_hotkey_works_with_ctrl_held`、`extra_modifier_does_not_trigger`、`releasing_modifier_first_still_stops`、`unrelated_keys_pass_through_untouched`

### 顺带修掉的两个隐患

| 问题 | 后果 | 修复 |
|---|---|---|
| 保存配置时不调用 `set_current()` | 手动输入/修改快捷键后**必须重启才生效**，用户以为坏了 | 保存即生效；格式非法则拒绝保存并红字提示 |
| 捕捉模式下按到不支持的键，钩子会被永久暂停（`paused` 无人复位） | 之后所有快捷键都没反应 | 窗口失焦 / 取消 / 关闭 都会退出捕捉 |

另外启动与变更都会写日志：`注册全局快捷键：Ctrl + ``、`快捷键已生效：…`、`快捷键按下 → 开始录音`，以后一眼能看出钩子在不在工作。

## 二、识别成功但文字不进光标

### 证据

日志里测试会话是**成功**的：

```
[1789025047] 麦克风已启动：48000Hz / 2ch / F32 → 重采样到 16000Hz
[1789025047] ASR 已连接：千问（阿里云百炼）
[1789025052] 识别完成（19 字）
```

文字出来了，但注入时**前台窗口是 BBVoxi 自己的设置窗**（你刚点完按钮），`SendInput` 就把字打给了本程序，看起来像"什么都没打出来"。

### 修复

1. **录音开始时收起设置窗**（快捷键与托盘触发时；测试模式保留，方便看结果），焦点回到你正在用的程序 —— 说话期间就已经对准目标窗口。
2. **注入前双重保险**：检测前台窗口是否属于本进程，是就先收起、等 150ms 让焦点回去，再打字。
