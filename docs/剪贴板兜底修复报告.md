# 「输入被拒时的剪贴板兜底」为什么兜不住 —— 诊断与修复报告

> 随 **1.3.2** 一并发布 ｜ 日期：2026-09-25
> 相关模块：[config.rs](../src/config.rs)、[typer.rs](../src/typer.rs)、[clipboard.rs](../src/clipboard.rs)、[session.rs](../src/session.rs)、[ui.rs](../src/ui.rs)

---

## 结论速览

主人报的是两件事，其实是**两个独立缺陷叠在一起**：

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 勾了「输入被拒时用剪贴板粘贴兜底」，可字没进目标程序、剪贴板里也没有 | 这个开关的触发条件**根本检测不到真正的失败**：`SendInput` 只报告"事件已入队"，目标程序**收下再丢掉**我们完全看不见。于是它从没触发过（日志里 5 个月零触发），而真正该兜底的那一档（字没打进去）**任何代码路径都不会往剪贴板写** | 把"兜底"改成**能兑现的形式**：识别结果**每次**都留一份到剪贴板（默认开），主人在哪儿、什么时候 Ctrl+V 都能拿到 |
| 2 | 即便在会写剪贴板的那条路径上（切走了窗口），事后也找不到那段字 | 兜底粘贴是**先存后还**：写完 300 毫秒后被"还原"，把我们自己写进去的那段字又擦掉了 | **去掉自动还原**；另外写完**回读核对**，对不上就如实写进提示 |

## 一、"输入被拒"这件事，我们根本检测不到

### 1.1 开关的承诺与代码的实际行为

界面上的说明是：「目标程序不认模拟按键时改走 Ctrl+V」。可是让它改走 Ctrl+V 的条件是：

```rust
match injector::type_text(&planned.append) {
    Ok(committed) if committed >= expected => {}          // 报"成功"就认定打进去了
    Ok(committed) => { /* 只进去了几个 → 改走剪贴板粘贴 */ }
    Err(e) => { /* SendInput 被拒 → 改走剪贴板粘贴 */ }
}
```

`SendInput` 的返回值是**"有多少事件进了系统输入队列"**，不是"目标程序收下了"。
目标程序（游戏、远程桌面、部分 Java/Electron、管理员权限窗口）把模拟按键整个忽略掉时，
`SendInput` 照样报"全部入队" —— 于是我们认定"输入成功"，兜底那条路**永远不会走**。

**日志佐证**：`%APPDATA%\BBVoxi\logs\bbvoxi.log` 里
`改用剪贴板粘贴兜底` / `逐字注入只提交了` 这两条**一条都没有** —— 这个开关从上线至今
一次也没触发过。这就是主人说的"这个功能无法正常使用"。

### 1.2 那能不能"核实"一下？——实测：不行

为了不靠猜，我用一次性注入探针在真机上测了"有没有办法看出这段字到底进没进去"：

| 目标 | 手段 | 结果 |
|---|---|---|
| 记事本（普通编辑框） | 注入后用 `GetGUIThreadInfo` 看插入符 | 能看到插入符（这条信号本身是通的） |
| **Chrome（输入框已聚焦）** | 同上：焦点窗口类名 + 插入符 | 焦点 = 顶层 `Chrome_WidgetWin_1`，**插入符为空** |
| **Chrome（页面上没有输入框）** | 同上 | 焦点 = 同一个 `Chrome_WidgetWin_1`，**插入符同样为空** |

**同一个 Chromium 窗口里，"聚焦在输入框"和"聚焦在没有输入框的页面"这两种情况，
从 Win32 侧看过去一模一样** —— 没有插入符、焦点类名也一样。
而 Chromium/Electron 正是主人日常用的目标（WorkBuddy、Cherry Studio 都是这一类）。
结论：**没有便宜可靠的"是否真的打进去了"的判据**，能靠的只有"留一份到剪贴板"。

（探针文件 `examples/caret_probe*.rs` 用完已删除。）

### 1.3 于是修复方向：把"兜底"落成能兑现的行为

- 「识别结果总留一份到剪贴板」**默认改为开**，并且**老配置自动迁移过来**
  （配置 version 1 → 2；主人现有的配置里这个值是老默认的 `false`，迁移时会被打开）。
  这样无论字有没有打进目标程序，剪贴板里都有一份，随时 `Ctrl+V`。
- 老配置里的 `false` 到底是"从没动过"还是"主人真的关过"，在文件里长得一样、分不出来；
  按"漏掉主人说的话"比"多覆盖一次剪贴板"更糟来取舍 ⇒ 统一打开。
  主人不想要，在设置里关掉即可（version 已是 2，不会再被打开）。

## 二、"事后在剪贴板里找不到"的第二个原因：我们把自己写进去的字擦掉了

旧代码在兜底粘贴时先看一眼主人的剪贴板，粘完 300 毫秒再"还原"回去：

```rust
clipboard::write_text(append)?;        // 把救回来的那段字写进剪贴板
let seq = clipboard::sequence();
injector::paste()?;                    // Ctrl+V 试一次
if let OriginalClipboard::Text(previous) = &self.original {
    clipboard::schedule_restore(previous.clone(), seq);   // 300ms 后把它擦掉
}
```

于是：**粘贴万一没成功（目标连 Ctrl+V 也不认），主人唯一的退路（自己 Ctrl+V 一次）
也在这 300 毫秒里被抹掉了**。他事后到剪贴板里找，自然什么都没有 —— 正是他报的现象。

**修法**：写完就留在那儿，不再自动还原；并且写完**回读核对**
（`clipboard::write_text_verified`）：`SetClipboardData` 报成功只说明内核收下了，
被别的程序当场改掉也是可能的 —— 对不上就在提示里如实说明，而不是让主人对着一句
"已复制到剪贴板"却什么也粘不出来。

## 三、改动清单

| 文件 | 改动 |
|---|---|
| `config.rs` | `keep_on_clipboard` 默认改为 `true`；`CURRENT_VERSION = 2` + `migrate()`（老配置升级时打开它，并写回、记日志）；新增 2 条迁移用例 |
| `typer.rs` | 删掉"先存后还"整套：`OriginalClipboard` / `should_snapshot` / 快照与还原调用（净删约 70 行）；`Fallback` 只剩 `paste` 一个字段 |
| `clipboard.rs` | 删除 `schedule_restore` / `sequence`；新增 `write_text_verified`（写后回读核对）；新增手测 `written_result_stays_on_the_clipboard`（回归"写的字被自己擦掉"） |
| `session.rs` | 结果留一份时用回读核对的写入并记明确日志；交付提示在回读失败时如实补一句 |
| `ui.rs` | 两个开关的说明**改成真话**（模拟按键有没有落进目标我们看不出来 / 代价是顶掉你复制的内容）；结果卡片里加一行淡字"这份结果也留在了剪贴板" |

| 项 | 结果 |
|---|---|
| `cargo test --bin bbvoxi` | **153 passed / 0 failed / 4 ignored**（新增 2 条迁移用例、1 条剪贴板手测；删掉 1 条随功能一起消失的用例） |
| `cargo test clipboard -- --ignored --test-threads=1` | **2 passed**（真剪贴板往返 + 新回归：写完 800 毫秒后内容仍在） |
| `cargo clippy`（本次改动的文件） | **零新增**（仍是既有那几条） |
| `cargo build --release` | ✅ |

顺带记一条踩坑：**两条剪贴板手测必须串行跑**（`--test-threads=1`）。`OpenClipboard(None)`
是**任务级**关联，并行跑时另一条用例的 `CloseClipboard` 会把我们的打开状态一起收走，
`EmptyClipboard` 于是报 `0x8007058A`（线程没有打开的剪贴板）—— 那是测试互相踩，
不是剪贴板有问题（已写进用例注释）。程序里只有一个会话线程碰剪贴板，不存在这个交叉。

## 五、请你实机验证

1. 退出托盘里的旧实例，运行新构建的 `target/release/bbvoxi.exe`。
2. 说一句正常的话（打进光标处），然后**随便找个地方 Ctrl+V** —— 期望：粘出来的就是刚说的话
   （也就是"结果始终留了一份"）。
3. 把光标放到**不会接收文字**的地方（网页空白处 / 图片窗口 / 游戏画面）说一句 ——
   期望：剪贴板里依然有这句话，随时可以粘到别处。
4. 录音途中切走窗口再说 —— 期望：没有窗口跳出来，剪贴板里有这句完整的话。
5. 打开设置窗，看「识别结果总留一份到剪贴板（推荐）」是否已勾上（老配置会被自动升级），
   以及结果卡片下方那行「这份结果也留在了剪贴板」。

## 六、已知取舍（都写进界面说明了，不是漏改）

- **开启"留一份"就会顶掉你原来复制的剪贴板内容** —— 这是把结果留在剪贴板这件事的必然代价
  （两者不可能同时占着剪贴板）。不想要这个代价就在设置里关掉，关掉后回到旧行为：
  只有"切走窗口/注入被拒"这类情况才写剪贴板，而且**不再自动还原**。
- **"字到底有没有打进目标程序"仍然无法核实** —— 所以不做"检测到没进去就自动再粘一次"：
  万一字其实进去了，再粘一次就会**打两遍**。留一份让主人自己决定才是安全的。
- **测试模式依然一个字符都不碰剪贴板**（既有契约，未变）。
- **会话中途失败**（网络超时、麦克风异常）：已识别到的部分也会留一份到剪贴板
  （随后的全量审查补上的，见 `session::keep_partial_on_failure`）—— 主人真正在意的
  就是"字没打进去时手里得有一份"，半路失败也一样。
