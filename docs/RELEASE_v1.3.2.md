1. **按住 `Ctrl + Win` 说话时，开始菜单会突然弹出来抢焦点**——根因是按键顺序：先按 Win 后按 Ctrl 时，Win 的按下被放给了系统，松开时必然弹开始菜单；

3. **那个提示会弹出软件窗口**——主人正在别的程序里干活，窗口自己跳出来打断工作。

## 6. 完整功能清单

### 6.1 本版修复（重点，三件大事）

**① `Ctrl + Win` 不再弹出开始菜单（核心）**

- 根因：旧实现的规则是"凑齐组合的那一次按下才吞"。**先按 Win、后按 Ctrl** 时，Win 的按下
  被放行给了系统外壳——外壳记住"Win 按下过"，松开时必弹开始菜单抢走焦点，
  正在说话的主人这一次结果就打不进目标程序（表现为"突然断开 + 弹出开始界面"）
- 修法：组合里含 `Win` 时，**Win 的按下由本程序全程接管**，之后按主人的真实意图补发：
  - 组合凑齐（两种按法顺序都算）→ 全程吞掉，**零补发**（不弹菜单、不留"Win 还按着"的假状态）
  - 只按了 Win → 补一整套 Win 按下+松开，**开始菜单照常可用**
  - `Win+E` 这类组合键 → 一次 `SendInput` 提交「Win↓ + 按键↓」，**系统组合键照常生效**
- 以上全部经注入探针在真机实测验证（见技术亮点 7.1）

**② 剪贴板里的结果不再被自己擦掉，并且默认就留一份**

- 「识别结果总留一份到剪贴板」**默认改为开**，老配置自动迁移（不想用可在设置里关掉）
- 兜底粘贴**不再"先存后还"**：以前写进去 300 毫秒后就被还原，主人事后到剪贴板里
  什么也找不到（他报的就是这个）
- 写入后**回读核对**：`SetClipboardData` 报成功只说明内核收下了，被别的程序当场改掉
  也可能——对不上就在提示里如实说明
- **会话中途失败**（网络超时、麦克风异常）时，已识别到的部分也会留一份

**③ 提示不再弹出软件窗口**

- 删掉整条"会话请求显示窗口"的通道：提示改走**托盘图标与悬浮文字**、
  设置窗里的提醒文字（愿意看时再看）、以及日志
- 结果卡片与状态胶囊都会如实显示「这份结果也留在了剪贴板」——而且**只在回读核对通过时**才说

### 6.2 本版修复（全量审查 10 项加固）

完整根因见 [全量审查与修复报告](./全量审查与修复报告.md)：

- [x] **麦克风启动无超时**：设备被独占/驱动卡死时，会话线程被永久卡住，之后**所有热键失效**、
      界面停在"录音中"，只能重启程序。现在 5 秒上限，超时如实报错
- [x] **配置迁移每次启动都跑**：主人自己把快捷键设成 Ctrl+反引号，下次启动会被悄悄改回默认值。
      现在迁移只在升级版本时执行（补回归用例 `migration_never_overwrites_a_current_config`）
- [x] **键盘钩子回调里做文件 I/O**：钩子被卡住会被 Windows **静默摘掉**（快捷键全失效且无声）。
      改为只记原子计数，日志由会话线程补记
- [x] **钩子线程把 `GetMessageW` 的 -1（出错）当成"还有消息"**：空转刷 CPU 且钩子已失效无声。
      改为按 `>0 / 0 / -1` 分别处理
- [x] **豆包响应解压无上限**：异常帧可把常驻进程内存吃光。现在 8 MB 上限，超出按坏帧处理
- [x] **`AsrClient::close()` 是死函数**：注释承诺"让服务端看到正常关闭"，却从没人调用。
      现在会话收尾时真正调用它
- [x] **单测往主人真实的日志文件里写**（日志里 205 条测试灌进去的假现场，排查时会被带偏）：
      测试构建只写 stderr
- [x] 删除与 `docs/界面截图.png` **字节完全相同**的重复素材
- [x] 依赖精简：去掉 `rustls` 的 `logging` feature（它只为接 `log` crate，而本程序没有任何 logger）
- [x] 结构精简：音频的四个共享句柄收成 `CaptureHandles`（不再穿四层调用）、`decide` 的 keyup
      分支收成 `after_keyup()`、`foreground_is_own()` 去重、单字段 `Fallback` 结构体内联

### 6.3 语音输入主线（延续）

- [x] 全局快捷键录音（按住说、松开输入，组合可自定义，默认 `Ctrl + Win`）
- [x] 边说话边打字：中间结果实时写入光标处，识别被修正时自动回退重打
- [x] 测试模式（5 秒）验证凭据与麦克风，结果只回显在窗口里（**不碰剪贴板、不外打一个字**）
- [x] 托盘常驻、关窗即最小化、双击 exe 唤醒后台实例、开机自启（静默）
- [x] 三家 ASR 可切换、单文件免安装

### 6.4 稳定性与可观测性（延续 + 本版增强）

- [x] panic 带文件/行号写日志；会话 `catch_unwind` 包裹，单次异常不带走程序
- [x] 日志本地时间戳、滚动（单份 2 MB + 2 份历史）、滚动失败退避；**测试构建不再写真实日志**
- [x] 音频缓冲满只丢帧不中断；停止时补发残料，并**等补发完成的标志**再收尾
- [x] 剪贴板被占用时重试 5 次（每次 20ms）；写入后回读核对并留痕
- [x] 补发 Win 键失败时在钩子里只记原子计数，由会话线程落日志（钩子回调零 I/O）

## 7. 技术亮点

### 7.1 为什么 `Win` 键的按下必须"全程接管"

`Win` 的按下一旦放给系统外壳就**再也擦不掉**：外壳记住"Win 按下过"之后，
- 让松开过去 → 开始菜单弹出、抢走焦点；
- 把松开吞掉 → 外壳以为 Win 一直按着，之后随便敲个字母都会触发 `Win+X`（打开资源管理器）。

两条路都用注入探针在真机上实测确认过，所以只剩"按下就接管、事后按主人真实意图补发"一条路。
而"只按了 Win"与"Win+X"两种补法也都实测过：补一整套按下+松开，开始菜单正常弹出；
「Win↓ + 按键↓」必须**同一次 `SendInput`** 提交——分两次提交外壳会先收到那个键，组合键失效。

### 7.2 为什么"先存后还"是错的

兜底粘贴的目的是救回"没打进去"的字。但"粘贴到底成没成"和"注入成没成"一样**无法核实**——
`SendInput` 只报告事件入队。于是"先写进剪贴板、300 毫秒后还原"等于把主人唯一的退路
（自己 Ctrl+V 一次）也抹掉：他事后到剪贴板里找，自然什么都没有。

### 7.3 为什么"打进去了没有"无法核实

用 `GetGUIThreadInfo` 看前台线程的焦点与插入符：Chrome 里**焦点在输入框**与**聚焦在空白页面**
两种情况，焦点类名都是 `Chrome_WidgetWin_1`、插入符都为空——从 Win32 侧看不出任何差别，
而 Chromium/Electron 正是日常主要目标。所以不做"检测到没进去就自动再粘一次"
（字若其实进去了会打两遍），只做"保证留一份"。

### 7.4 尾帧为什么"等标志"而不是"睡固定时长"

停止录音后，残留样本要靠采集回调补发；回调周期在蓝牙免提/部分 USB 声卡上能到 100ms 以上。
固定睡 60ms 会在回调到来之前把流 drop 掉，尾巴照样丢。现在采集侧补发完（或无残留可补）
会置位 `tail_flushed`，会话侧等这个标志（上限 300ms），两端都有界。

### 7.5 钩子回调为什么禁止 I/O

低级键盘钩子必须毫秒级返回；`log()` 要抢锁、写磁盘，一旦被卡住（杀软扫描、磁盘忙），
Windows 会**静默摘掉钩子**——表现是"快捷键全失效、Win 键开始乱弹"且日志为空。
所以钩子回调里只准动原子变量，日志一律由会话线程补记。

## 11. 已知问题与限制

- 目标窗口以**管理员权限**运行时无法输入（Windows 系统限制），`Ctrl+V` 同样被拦——
  但结果仍会复制到剪贴板，粘到普通权限的窗口里就行
- **焦点不在任何输入框里**时，注入和粘贴都不会生效——这正是 1.3.2 把"留一份"改为默认开的原因：
  随时 Ctrl+V 都能拿到刚说的话
- 极少数程序会"**假装收下了**"我们的输入：Windows 没有通用接口能查证（实测 Chrome 连插入符
  都不报告），所以本版不做"检测到没进去就自动再粘一次"——字若其实进去了会打两遍
- **开启"留一份"会顶掉你原来复制的剪贴板内容**：这是把结果留在剪贴板的必然代价；
  不想要就在设置里关掉（关掉后回到旧行为：只有切走窗口/注入被拒才写剪贴板，且不再自动还原）
- 含 `Win` + 普通主键的组合会被系统抢先响应（截图、锁屏等）——Windows 保留键的既定行为
- 剪贴板只能保住**文本**：你原来复制的是图片或文件时无法还原（系统机制限制）
- **老配置升级说明**：`keep_on_clipboard` 老默认是关的，本次迁移会统一打开；若你确实不想要，
  在设置里关掉即可（迁移只发生一次，之后不会再被打开）
