> **Release: BBVoxi 1.3.1 — 快捷键全面自定义 + 开机静默启动 + 全量审查加固**

## 4. 安装与首次运行

1. 把 `BBVoxi-1.3.1.exe` 放到任意目录（推荐 `%LOCALAPPDATA%\BBVoxi\`）
2. 双击运行：右下角出现 BBVoxi 托盘图标（已有旧版在运行则直接唤醒并弹出设置窗）
3. 设置窗里选服务商、填 API Key（腾讯云填 App ID / Secret ID / Secret Key 三元组）
4. 点「测试识别（5 秒）」说一句话确认能出字（**结果只显示在窗口里**，不会往外打字）
5. 点「保存」，之后关闭窗口 = 最小化到托盘
6. 在任意程序的光标处按住快捷键（默认 `Ctrl + Win`）说话，松开即输入

- **卸载**：直接删除 exe；配置与日志保留在 `%APPDATA%\BBVoxi\`
- 可选「开机自启」写在设置窗的「通用」卡片里；**勾选后请重新勾一次**（见第 12 节）
- 设置窗底部有**「项目地址」**按钮：点击后用系统默认浏览器打开本项目主页

## 6. 完整功能清单

### 6.1 本版新增与改进（重点）

**① 快捷键全面自定义（核心）**

- [x] 修饰键支持 `Ctrl / Alt / Shift / Win`，**任意 1~4 个搭配**，且**不限制松手顺序**（录制时"只增不减"，先松哪个都不会丢）
- [x] 主键覆盖：字母 A~Z、数字 0~9、`F1`~`F24`、空格、方向键、翻页键（Page Up/Down）、Home/End、符号键等**全部可录制主键**
- [x] **默认快捷键改为 `Ctrl + Win`**（左 Win / 右 Win 都认）
- [x] 两条安全线：**单个修饰键**（如只按 `Ctrl`）与**单个普通键**（如只按 `A`）不会被设为快捷键 —— 那会与系统/输入法功能打架
- [x] **旧配置自动升级**：配置文件里若是老默认值 `ctrl+\``，启动时自动升级为 `ctrl+win` 并写回文件；**主人自定义过的组合一律不动**
- [x] 组合键里含 `Win` 时，`Win` 键在 Windows 里是系统保留键（开始菜单），按下时系统可能抢先响应 —— 这是平台行为，已在提示文案中说明

**② 开机静默启动**

- [x] 自启项写为 `"...\BBVoxi-1.3.1.exe" --autostart`：开机拉起时**不弹任何窗口**，直接缩在托盘后台
- [x] 手动双击 exe 仍照常弹出设置窗（用"系统开机 5 分钟内 + 老格式启动项"两个条件区分，绝不误判）
- [x] 老版本（启动项里没有参数）升级后**第一次开机**就会被正确识别为自启，并顺手把注册表项升级成新格式

**③ 结果交付更可靠**

- [x] 录音途中切走窗口、或注入失败时：**一个字都不往别处打**，同时把完整结果放进剪贴板并弹出提示（本版修掉了"提示弹不出来"的缺陷）
- [x] 收尾时若主人还在别的窗口，结果同样走剪贴板，绝不"重打进新窗口"

### 6.2 本版修复（全量审查 31 项）

按影响程度分级列出（完整根因见 [全量审查与修复报告-v1.3.1.md](./全量审查与修复报告-v1.3.1.md)）：

**【严重】会丢字 / 卡死 / 卡界面**

- [x] **录音尾巴固定丢最多 100 毫秒语音**：停止录音后，重采样器里还压着的样本与不足一帧的残料会随流一起丢弃。现在停止时把它们**补发**出去（不补假静音），并给采集线程 60 毫秒收工时间，消除"补发还没进通道就被收干丢掉"的竞态
- [x] **麦克风出问题却一直显示"录音中"**：拔掉麦克风 / 被别的程序独占时，采集回调只写日志，界面永远停在录音态、会话收不到结束信号。现在会立刻叫停采集、如实报「麦克风异常：xxx」
- [x] **网络半死时整个会话卡死**：Wi-Fi 掉线（无 RST）时 `send` 会永久挂住，松开快捷键也收不到，之后所有热键都失灵。现在所有网络发送与收尾步骤都有 5 秒超时，最坏 5 秒收场
- [x] **收尾"边录边发"结束不了**：原实现先清空缓冲再去释放麦克风，导致"永远有新帧可读"。改为**先停麦克风 → 再收干残留 → 最后释放**
- [x] **注入失败后结果被静默丢弃**（1.3 已修的延续加固）：收尾三态化（成功 / 放弃 / 失败），两种非成功情况一律改走剪贴板
- [x] **"让主人看提示"却弹不出窗口**：会话线程请求显示设置窗时，会被主窗口每帧的"隐藏"指令盖掉。改为**请求位机制**，由 UI 线程走正规显示流程
- [x] **逐字注入只打进去一半时整段重粘 → 重复打字**：现在只把**没打进去的尾巴**交给剪贴板补上

**【中等】数据与状态不一致**

- [x] **豆包二遍识别会丢后半段 / 重复**：原来用"只增不减的数组下标"追定稿，服务端重排或缩短数组后，后面的定稿全丢、改写版又被当成新句追加。改为**整段快照 + 固定编号替换**，重复帧被挡掉、改写帧整段覆盖
- [x] **腾讯云的中间结果看不到**：`slice_type = 0`（语音中间结果）被当成"忽略"，现在非终包按中间结果、终包按定稿处理
- [x] **退格 / 回车 / Tab 在部分程序里失灵**：命名键以前只发虚拟键码、扫描码为 0，只读扫描码的程序（游戏、部分远程桌面）看不见。现在统一由系统映射表取真实扫描码
- [x] **服务端帧无上限堆内存**：改为 64 格有界通道，满了丢帧 + 限流日志（首条与每 64 条各记一次），读取任务永远向前走
- [x] **剪贴板清空失败会漏掉一块系统内存**（`GlobalFree` 缺失）；**剪贴板写入顺序**已确保"先把新内容准备好、最后才清空"
- [x] **豆包坏帧被悄悄吞掉**：现在记录帧长与前 16 字节的十六进制，连续 5 帧解析失败则如实报错结束会话
- [x] **开机自启误判**（1.3 引入修复的加固）：加了"系统开机 5 分钟内"条件并抽成纯函数，把手动双击与开机拉起彻底分开
- [x] **窗口最小化后从托盘打不开**：显示窗口的顺序修正为「先解除最小化 → 再显示 → 延后一帧抢焦点」
- [x] **抢前台经常失败**：显示与抢焦点不再同一帧下发（跨帧后成功率显著提高）
- [x] **托盘图标创建失败就永久放弃**：改为每 30 秒退避重试，托盘服务恢复后自动补上
- [x] **日志重入死锁**：panic 钩子写日志时可能重入同一把锁。现在有重入保护，**绝不自死锁**
- [x] **日志滚动掉一根边**、**滚动失败被静默吞掉**：判定改为 `>=`，失败回退 60 秒退避并留痕
- [x] **配置损坏时静默用默认值**：现在记日志；临时文件名为 `config.<进程号>.tmp`，多实例不会互相覆盖

- [x] 单实例互斥量创建失败、界面创建失败等路径补齐日志留痕
- [x] 打包脚本补 `cargo:rerun-if-env-changed=RC`

## 7. 技术亮点

### 7.1 为什么"只增不减"的下标追踪必错（豆包）

服务端二遍识别（`definite=true`）会**改写、甚至重排/缩短** `utterances` 数组。用下标当游标时：数组一缩，`while consumed < list.len()` 永不成立 → 后面的定稿全丢；改写版落到"新下标"又会被当成新句追加 → 主人看到"多打一份字"。
改成**「上次报出去的完整快照」做比较基准 + 固定片段编号**后，重复帧被挡掉、改写帧触发上层"同号替换"，彻底不依赖下标。

### 7.2 为什么尾音必须"补发而不是补零"

ASR 接受任意长度的 PCM。停止录音时把重采样器里压着的真实样本发给服务端，比"后面接一段假静音"更准；再配合 60 毫秒的采集线程收工等待，主人松手前那几个字才真正不丢。

### 7.3 快捷键录制为什么用"只增不减"

录制时按下 `Ctrl`、再按下 `Win`、然后先松开 `Ctrl` —— 若按"当前按住的键"实时取值，最后的组合就只剩 `Win`。改为**"按下即记、只增不减"**，松手顺序任意都不会丢修饰键；提交时再与主键合并去重。

### 7.4 `Win` 键的两条平台约束（刻意保留）

1. 开始菜单在 `Win` **松开**时弹出 —— 所以纯修饰键组合必须先按 `Ctrl` 再按 `Win`；
2. 含 `Win` + 普通主键的组合会被系统抢先响应（截图、锁屏等）—— 这是 Windows 保留键的既定行为，不是本程序的 bug。

### 7.5 三级输入兜底（延续 1.3）

`SendInput + KEYEVENTF_UNICODE`（逐字注入）与 `Ctrl+V`（剪贴板粘贴）在 Windows 里是**两条完全不同的通道**：忽略前者的程序（远程桌面、部分 Electron/Java/老 MFC）往往认后者。所以"逐字注入被拒"不是终点；连粘贴也不安全时，第③级只放剪贴板并提示。

### 7.6 网络层的三条保险（本版新增）

- 发送超时（5 秒）：半死连接不再让会话永久挂起
- 有界帧通道（64 格）：服务端畸形推送不会把内存吃光
- 收尾总超时（8 秒）+ 每一步独立超时：任何一步异常都不会把会话挂在收尾阶段

## 11. 已知问题与限制

| 限制 | 现状 |
|---|---|
| 仅 64 位 Windows | 未覆盖 Win7 / 32 位 |
| 仅中文识别 | 语言不暴露 |
| 管理员权限窗口输入失败 | Windows UIPI 限制，给出明确提示；`Ctrl+V` 同样被拦 —— **但结果仍会复制到剪贴板**，粘到普通权限窗口即可 |
| **焦点不在输入框时注入/粘贴都无效** | 两者都要靠前台焦点接收，只能靠「识别结果总留一份到剪贴板」兜住 |
| **程序"假装收下了"字**（注入报成功、目标程序悄悄丢弃） | Windows **没有**通用接口能查证；本程序用「识别结果总留一份到剪贴板」开关兜住数据安全 |
| **同一窗口内主人自己挪了光标** | 光标位置只存在于目标程序内部，**无法检测**；此时若发生纠错退格，可能删到非预期位置（已知限制，代码注释中已标明） |
| 录音中途切走窗口 → 本次不自动输入 | 防打错地方的设计；一直没回来的话把结果放进剪贴板并提示 `Ctrl+V` |
| 含 `Win` + 普通主键的组合会被系统抢先响应 | Windows 保留键的既定行为（开始菜单在 `Win` 松开时弹出） |
| 兜底粘贴短暂占用剪贴板 | 粘贴成功后延迟约 300ms 还原；那一次会进 Windows 剪贴板历史（`Win+V`） |
| 剪贴板只保得住文本 | 主人原来复制的是图片/文件时无法还原（延迟渲染），日志会写明"不还原" |
| 剪贴板被占用时等待上限 80ms | 仅兜底路径；换来的是"绝不把全系统剪贴板锁死" |
| 多麦克风选择 UI | 自动选系统默认设备 |
| 腾讯 `Hy-ASR-3.0-preview` 单次上限 60 秒 | 服务端限制（千问/豆包无此限） |
| 豆包「高精度」模式无中间结果 | 该模式下实时输入看不到逐字上屏，属协议特性 |
| 资源占用 | 工作集约 114~170 MB（egui 基线） |
| `cargo fmt --check` 不通过 | 仓库历史代码与当前 rustfmt 版本存在格式差异（非本版引入） |

## 12. 升级指南（任意旧版 → 1.3.1）

1. 退出正在运行的 BBVoxi（右键托盘 → 退出）
2. 用 `BBVoxi-1.3.1.exe` 覆盖旧 exe（无需卸载、无需重填配置）
3. 双击运行后，**核对设置窗右下角是否为 `v1.3.1`**
4. **重新勾选一次「开机自启」**：注册表里的自启项指向的是旧 exe 路径，重勾才会更新为新版
5. 建议在新版里**重新录制一次快捷键**（也可以什么都不做 —— 老默认值会被自动升级为 `Ctrl + Win`）

> **行为变化提醒**：
> - 默认快捷键由老默认值变为 **`Ctrl + Win`**；主人自定义过组合的配置**不会被改动**
> - 开机自启现在是**静默启动**（不弹窗）；想打开界面请双击 exe 或点托盘图标
> - 录音失败、放弃输入时会多一步"弹出设置窗显示提示"，那是为了让主人看见结果已放进剪贴板
