# BBVoxi 1.3.3 版本发布说明

> **Release: BBVoxi 1.3.3 — 界面一屏看全（方案 C）· 7 条硬伤修复 · 浅色主题对比度达标**

## 6. 完整功能清单

### 6.1 界面重排（方案 C，本版重点）

| 指标 | 1.3.2 | 1.3.3 |
|---|---|---|
| 内容总高 | 1274px | **692px**（省 46%） |
| 卡片数 | 5 张 | **2 张** |
| 「最近识别」位置 | 599px 处（768 高的笔记本上**完全看不见**） | **98px**（第一眼就能看到实时文字） |
| 768 高的笔记本 | 要滚 744px | 滚 136px |
| 900 高的窗口 | 还要滚 612px | **一屏看全** |

做法与理由：

- [x] **结果卡提到品牌栏正下方**：测试录音时不用滚动就能看到实时文字（旧版把它排在三张配置卡之后，
      恰好在最需要看实时文字的笔记本上失效）
- [x] **服务商 / 凭据 / 快捷键 / 识别选项 / 通用 合并成一张设置卡**：字段与标签同排（标签左、控件右），
      取消「高级（业务空间专属域名）」折叠（接口地址就是普通一行），分组用细分割线
- [x] **所有说明文字收进悬停气泡**（右侧小 `i` 图标）：一句话都没删，但页面不再被说明小字占掉 30% 高度
      （旧版 340px 的说明文字现在只在需要时展开）
- [x] **品牌栏压到 42px**（图标 36 + 名称 + 一行副标题）
- [x] **底部三按钮收窄**：140/104/96 → 130/104/92
- [x] 加分项（零成本启用）：卡片柔和投影、状态切换 0.12 秒过渡、滚动条平时隐藏（滚轮照常可滚）

### 6.2 界面配套修复（6 项）

- [x] **浅色主题对比度达标（按 WCAG 2.x 相对亮度公式逐对实测）**：
  - 成功绿 `#12A150` → `#0A7038`（3.37 → **6.20**）；警告橙 `#C77A00` → `#8A5200`（3.38 → **6.39**）；
    危险红 → `#B7220F`（**6.46**）
  - 顶部状态胶囊上的小字：2.88 → **5.0+**（透明度与文字色是成对算出来的，不是拍脑袋）
  - 「自动添加标点 / 口语顺滑」被禁用时：1.99（等于隐形）→ **5.5**（禁用透明度 0.5 → 0.65）
- [x] **状态消息 10 秒后自动退场**：旧版一条「已保存」会永远挂在界面底部（且没有任何清除点），
      还会把卡片越顶越高
- [x] **关窗有未保存改动时先确认**：新增对话框（保存并关闭 / 不保存 / 取消）；保存失败会把原因
      直接显示在对话框里（对话框是前景层，否则会盖住底部的提示）
- [x] **补上 `noninteractive.fg_stroke`**：旧版没覆盖它，深色主题下"正文"（5.12）反而比"次要文字"（6.68）更淡，层级颠倒
- [x] **字号收敛到 4 档语义名**（Heading / Body / Button / Small + Monospace）：旧版 47 处硬编码的
      11/11.5/12/13/13.5/14/15/21，想整体调一次字号必然改漏
- [x] **对比度单测换成真 WCAG 校验**：旧用例只比较 R 通道差值，上面那些 2.88 / 3.37 一个都抓不到
      （报告点名的"假安全网"）——换公式后它一次性抓出 **10 处**不达标

### 6.3 功能硬伤修复（两批共 7 条）

**第一批（直接丢字 / 重复打字）**

- [x] **会话中途失败不再丢最终结果**（旧版 `session.rs` 三条路径直接 `return`）：
      麦克风异常 / 推流失败 / 推流超时以前会跳过"给服务端发结束指令、松手后等最终结果、正常关闭"
      三件事 —— 服务端其实已经把这句话定稿了却没人去取。现在失败与正常路径**共用同一套收尾**
      （发结束帧 → 等最终结果 → 关连接），结果照样交付（能打字就打字、否则进剪贴板），
      并如实报出失败原因；链路已经坏掉时把等待窗口从 8 秒收到 2 秒，不陪它干等
- [x] **会话线程起不来，界面看得见**：tokio 运行时或线程创建失败以前只写日志 ——
      之后按快捷键、点测试、托盘命令全部石沉大海，而窗口一切正常。现在写进界面状态（托盘与设置窗一起亮）
- [x] **生僻字 / emoji 的退格数按 UTF-16 编码单元算**：注入是按编码单元送的（一个代理对两次事件），
      删除也必须按同一口径数 —— 按"字符"数会少退一位，在目标程序里留下半个代理对的乱码；
      顺带修掉 `\r` 被算进退格数的问题（`\r` 不产生按键）
- [x] **注入部分失败不再整段重粘**：`SendInput` 分批提交时，某一批整批被拒以前会丢掉"已经打进去多少"的
      记账，于是把**整段**再粘一遍 → 目标程序里出现两份同样的字。现在统一报出"从开头连续进去了多少"，
      只补没进去的尾巴；批内部分成功也会立刻停止后续批次（保证"缺的一定在末尾"这个前提成立）

**第二批（判断错误 / 静默失败）**

- [x] **陈旧错误码不再误判**：`SendInput` 成功时不写 `GetLastError`，旧版照读，于是几百毫秒前留下的
      "拒绝访问(5)"会把"部分成功"误判成被 UIPI 拦下、白跳过粘贴兜底。现在发之前先清错误码，
      且只在"一个事件都没进去"时才读它
- [x] **注入搬出键盘钩子回调**：回调里直接 `SendInput`，一旦被卡过系统 300ms 的超时，
      Windows 会**静默摘掉钩子**（快捷键全废、Win 键乱弹、日志里什么都没有）。现在回调只把任务
      丢进无界通道，注入由专用线程执行（失败也由它记日志）
- [x] **全局钩子装不上要报出来**：`SetWindowsHookExW` 失败以前只写日志、程序"一切正常"，
      实际一个键都没接管。现在会明确告诉主人（含"请重启程序"）

### 6.4 语音输入主线（延续）

- [x] 全局快捷键录音（按住说、松开输入，组合可自定义，默认 `Ctrl + Win`）
- [x] 边说话边打字：中间结果实时写入光标处，识别被修正时自动回退重打
- [x] 测试模式（5 秒）验证凭据与麦克风，结果只回显在窗口里（**不碰剪贴板、不外打一个字**）
- [x] 输入失败三级兜底：逐字注入 → 剪贴板粘贴 → 只放剪贴板并提示
- [x] 托盘常驻、关窗即最小化、双击 exe 唤醒后台实例、开机自启（静默）
- [x] 三家 ASR 可切换、单文件免安装

## 7. 技术亮点

### 7.1 界面改动怎么"不开窗"验收

本工程不做 GUI 测试（慢、不稳、还量不到坐标）。改版靠一套**无窗口布局探针**：
用一个 headless 的 egui 上下文跑**同一份 `SettingsApp::ui`**，把这一帧真实的绘制指令（矩形与文字）
抓出来量尺寸 —— 报告里的 1274px / 599px 是这么来的，改版后的 692px / 98px 也是这么复核的。
它现在还是回归测试：`content_is_compact`（总高 ≤ 700px、卡片正好 2 张）、
`result_card_is_on_the_first_screen`（「最近识别」必须在首屏）、
`no_text_overflows_the_window`（任何文字都不许被挤出窗口）等 6 条常驻测试集。

### 7.2 为什么状态胶囊的底色不能"加深"

报告建议把胶囊底色透明度从 14% 提到 25%（让它更显眼），但底色越深、上面那行 12px 的字对比度越低 ——
按 WCAG 公式实测，25% 会把字压到 4.5:1 以下。所以本版反过来做：**底色保持低透明度、把文字色加深**
（浅色主题的 ok/warn/danger 就是为此调深的），实测字与底 5.0:1 以上。

### 7.3 为什么"批内部分成功"必须停止后续批次

上层只会在**尾巴**上补粘（"没打进去的那段一定在末尾"是那条规则的前提）。
如果某一批只进去一半、我们还继续发后面的批次，缺口就会留在**中间** ——
补尾巴会把已经打进去的内容重复一遍，屏幕上出现前后错位的两份字。所以一发现批内部分成功就立刻停。

### 7.4 为什么注入必须搬出钩子回调

低级键盘钩子回调必须在毫秒级返回。回调里直接 `SendInput` 时，只要被卡过系统的
`LowLevelHooksTimeout`（300ms，杀软扫描、输入法、远控软件都能拖慢它），Windows 会**静默摘掉钩子**：
快捷键全废、Win 键开始乱弹，而日志里什么都没有。现在回调只做两件事：写原子状态、把补发任务丢进通道。

### 7.5 变异验证：怎么证明回归测试真的有效

本版 4 条关键回归测试都做了**变异验证** —— 把旧 bug 人为放回代码里，确认测试真的变红：
`Err` 时丢掉已提交计数 → `a_rejected_batch_keeps_the_units_already_committed` 变红（left 0 vs right 11）；
把旧错误码规则放回 → `stale_error_code_never_turns_a_partial_success_into_denial` 变红；
断线当正常收场 → `a_silent_connection_drop_counts_as_a_failure` 变红；
胶囊把"照例留一份到剪贴板"当异常 → `a_routine_clipboard_copy_does_not_turn_the_pill_into_a_warning` 变红。
（过程中还靠它发现了一条测试覆盖漏洞：被拒的那批原本走的是"收尾提交"路径，测不到循环内的失败分支，已改成三批文本。）

## 11. 已知问题与限制

**与上一版相同的限制（未变化）**

- 目标窗口以**管理员权限**运行时无法输入（Windows UIPI 限制），会给出明确提示。**剪贴板兜底也救不了它**：
  `Ctrl+V` 走的同样是 `SendInput`，一样被拦 —— 但结果仍会复制到剪贴板，粘到普通权限窗口里就行
- 极少数程序会"**假装收下了**"我们的输入：Windows 没有通用接口能查证（实测 Chrome 连插入符都不报告），
  所以不做"检测到没进去就自动再粘一次"——字若其实进去了会打两遍；「总留一份」就是为这种情况准备的
- **录音途中切走窗口 → 结果不自动输入，改放进剪贴板**：这是"不打错地方"的安全设计
- 含 `Win` + 普通主键的组合会被系统抢先响应（截图、锁屏等）——Windows 保留键的既定行为
- **开启"留一份"会顶掉你原来复制的剪贴板内容**（可以在设置里关掉）
- 剪贴板只能保住**文本**：原来复制的是图片或文件时无法还原（系统机制限制）
- 腾讯 `Hy-ASR-3.0-preview` 引擎 60 秒上限；豆包「高精度」模式下实时输入看不到逐字上屏

**本版明确"不做"的（如实说明，不是遗漏）**

- **ASR 协议层的三条已知问题**（服务端结束帧被当普通帧丢弃、腾讯云丢掉官方句子序号、
  豆包"整段文本"兜底分支走不到）不在本版拍板范围内，保持原样；报告里列了源码位置，下轮可处理
- **钩子的存活检测 / 自动重装**：Windows 没有"查询低级钩子是否仍生效"的 API，硬做只能靠自测注入，
  误判代价大于收益；本版改为从根因上降低被摘风险（注入移出回调）
- **收尾 8 秒内按的键会被忽略、默认快捷键会吞掉所有 `Win+Ctrl` 组合**：属"值得知道"一类，
  本版未动

**界面上的刻意取舍（与报告建议不同，均为有意保留）**

- **副标题留在明面上**（报告建议挪进气泡）：它是新手唯一能立刻看到"按住什么键说话"的地方；
  已批准的界面预览图里副标题也是在明面上的
- **被禁用的选项用"提高透明度"而不是换一个更深的禁用色**：可读性目标已达成（1.99 → 5.5:1），
  这样能保持 egui 原生的"禁用外观"
- **状态胶囊底色透明度 0.12 而非报告建议的 25%**：见 7.2（按 WCAG 公式算出的安全值）

## 12. 升级指南（任意旧版 → 1.3.3）

1. 退出正在运行的旧实例（托盘图标右键 → 退出）
2. 用 `BBVoxi-1.3.3.exe` 覆盖旧 exe（推荐放在同一目录，开机自启的路径就不用改）
3. **本版没有配置迁移**（配置版本仍为 2），所有设置原样保留：服务商、凭据、快捷键、识别选项、开机自启
4. 界面会变成新布局（2 张卡 + 悬停说明气泡）；若一时找不到某项设置，把鼠标停到右侧的小 `i` 上看说明
5. 若之前升级过 1.3.1，请确认「开机自启」仍指向新 exe 的路径（见 1.3.1 升级指南第 3 条）

## 13. 安全与隐私声明

- 音频只在按下快捷键期间采集，并直接推送到你在设置里选择的服务商；本程序**不采集、不上传**
  任何其他数据，无遥测、无统计
- 配置与日志只落在本机 `%APPDATA%\BBVoxi\`；日志不含音频与密钥（密钥只存配置文件）
- 剪贴板只在本机读写，用于"结果留一份"与兜底粘贴，不会把剪贴板内容发送到任何地方
- 本版新增的界面文案（气泡里的说明）全部是本地静态文本，不涉及任何网络请求

## 14. 反馈渠道

- 仓库 Issues：附上 `%APPDATA%\BBVoxi\logs\bbvoxi.log`（自动滚动，不含音频与密钥）
- 复现步骤尽量给出：服务商、目标程序、按键顺序（先 Win 还是先 Ctrl）、是否切过窗口
- 界面相关的问题请附上屏幕分辨率（本版的紧凑布局在 768 高的笔记本上仍需滚动约 136px）
