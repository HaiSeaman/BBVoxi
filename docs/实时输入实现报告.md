## 二、成熟方案：实时输入 + 自动纠错（本次实现）

### 为什么不能"来一段打一段"

语音识别的中间结果**会被不断修正**：同音字纠错、补标点、改断句。如果每来一版就往后追加，屏幕上会留下错误的前缀，比如先说成"今天天汽"再改成"今天天气"，直接追加就会变成"今天天汽今天天气"。

### 采用的做法（Windows 语音输入、安卓输入法都是这个思路）

维护两个状态：

- `sent`：**已经打进目标程序**的文本
- `desired`：**当前期望**的文本（已定稿部分 + 当前句的中间结果）

每次中间结果更新时，算 `sent` 与 `desired` 的**最长公共前缀**：

```
backspaces = sent 比公共前缀多出来的字符数   → 先发这么多次退格
append     = desired 比公共前缀多出来的部分   → 再打这部分
```

效果：

| 情况 | 动作 |
|---|---|
| 文字变长（正常说话） | 只补打新增的 1~2 个字，几乎无感 |
| 识别纠正了某个字（天汽→天气） | 只退格 1 次、重打 1 个字 |
| 定稿补了句号 | 只补打 1 个字符 |
| 整句被重写 | 退格整句再重打（少见） |

这就是"文字不停地输出显示"的实现方式，同时也保证松手时屏幕上的文本**必然等于最终识别结果**（收尾会再做一次对账同步）。

### 附带的安全设计

- **中途切走窗口就停止实时输入**：录音开始时记住前台窗口，若用户切到别的窗口，立即停止实时打字（否则退格会砸到别人的输入框里），改到收尾时按当时的焦点一次性输入。
- **测试模式永不外打**：点「测试识别」只在窗口里显示结果，不会往别的程序打字。
- **可关闭**：设置里「识别选项 → 边说话边打字（实时输入）」取消勾选，就回到"松手后一次性输入"的老行为。

### 想让出字更快可以调的参数（都已按官方建议设为默认）

| 服务商 | 参数 | 现状 |
|---|---|---|
| 千问 | `semantic_punctuation_enabled` | 保持 `false`（VAD 断句，延迟低）；如想更快结句可调小 `max_sentence_silence`（默认 1300ms） |
| 千问 | `heartbeat: true` | 已开启，静音时不断连 |
| 豆包 | `StreamMode: 2` + `enable_nonstream: true` | 已开启（实时分段 + 二次优化） |
| 腾讯 | `needvad: 1`、`convert_num_mode: 1` | 已开启 |

## 五、请你验证

1. 用记事本或微信输入框，**按住快捷键慢慢说一句长话**：文字应边说你边出现（不是等松手才一次性出现）
2. 故意说一个容易被纠正的词，看它是否自动改正（不会留下错误前缀）
3. 松开后文本应与识别最终结果完全一致
4. 若你更喜欢"松手再一次出字"，把「边说话边打字（实时输入）」取消勾选即可
5. 有任何异常，请发 `%APPDATA%\BBVoxi\logs\bbvoxi.log`（日志会记录"实时输入已关闭：录音过程中切换了窗口"这类状态变化）
