# Taste — generalizable preferences
- 未经明确许可，禁止执行任何 git 操作（不建分支、不提交、不切换/改工作树）；改动直接落在工作区，提交与否由用户自己决定。需要 git 时先请示，明确同意后也只做只读查看（status/diff/log）。 Confidence: 0.9
- 要求"多思考、多分析、多验证"后再动手，强调保证代码与逻辑的正确性；完工必须通过测试与验收，不接受"看起来没问题"。 Confidence: 0.9
- 使用中文沟通（报告、说明、结论都用中文）；代码注释与用户可见文案也用中文。 Confidence: 0.85
- 环境是 Windows：给出的命令必须是可直接粘贴执行的 PowerShell，不出现 ls/grep/cat/rm 之类 Unix 写法。 Confidence: 0.7
- 测试只做无界面（命令行/单元测试）方式，不跑 GUI/开窗验证；真机界面验收留给用户自己运行。 Confidence: 0.7
- 界面偏好简洁美观、看得舒服：倾向精简布局、合并卡片、把冗长说明收进悬停提示，让关键信息一屏可见。 Confidence: 0.6
- 把独立代码审查当作交付流程的固定一环：会主动用 `/code-review` 要求按严格流程全面审查代码、功能模块与逻辑问题，挖潜在 bug，处理完再跑测试验收。 Confidence: 0.8
- 发布/交付偏好：一版改动做完后，要求把本版改动的分析总结同步进**全部**开发者文档（README、版本历史、发布说明、发布文案等），不留过期的版本号或统计数字。 Confidence: 0.75
- 发布文案要整理成"可直接整块复制粘贴"的成品文本交给用户，GitHub 的实际发布动作（建 Release、上传 exe 等）由用户自己完成。 Confidence: 0.75
- 发布产物按版本号命名（如 `BBVoxi-1.3.3.exe`），并要求版本号在多处保持一致（Cargo.toml / 界面显示 / exe 文件名 / Release tag）。 Confidence: 0.7
